# Linguist Agent

游戏本地化的翻译与审校助手，在 DeepSeek Harness（DSH）中使用。

整理项目文件、术语和翻译记忆，完成翻译、全量审校与校对；在双语 CAT 工作台中使用行内标签 chip、不可见字符、术语提示、用例检索和修改差异辅助编辑，处理 QA 问题并导出支持的文件。编辑辅助的开关、项目词典与真实长度约束见 [快速开始](QUICK_START.md#编辑辅助)。

**第一次使用：安装插件 → 新建项目并导入文件 → 说明要做的工作。**

## 安装

当前适配基线为 **官方 DSH 0.2.2-rc.1**。已在本机 **macOS Apple Silicon** 验证原生安装与插件热加载，确认组件运行，以及 CAT 句段、确认状态、变量、颜色标记和链接边界正常显示。本轮尚未验证真实客户平台任务，其他系统和宿主版本尚未验证。

1. 打开官方 DeepSeek Harness，完成首次初始化与模型登录。
2. 确认 DSH 版本与上述基线一致。该版本已内置 LA 所需的自动化服务。
3. 在插件管理中选择维护者提供的 **linguist-dsh-plugin-1.3.5.tgz** 本地安装包，完成后选择“立即启用”；中文插件列表中显示为 **Linguist Agent · 游戏本地化**，点击条目可阅读包内详情，包含功能、开始使用、保存与兼容说明；详情语言跟随 DSH 界面语言，不支持的语言回退到英文。项目数据保留。升级到本版后，请在当前任务保存停稳后重启一次 DSH，移除旧 Agent 的额外工具结果裁剪；原会话可以继续使用。普通代码更新仍支持热应用。
4. 打开左侧 **Linguist**。首次使用会自动建立数据目录与持久安装标识，无需填写作者路径；已配置的目录、标识和通知设置继续使用。

截至 2026-10-02，仓库提供公开源码，没有 GitHub Release 安装包；本轮产物在本机生成。构建方式见 [开发说明](CONTRIBUTING.md)。

浏览器工作需要配套的 **BrowserSkill 0.4.1-la-dsh.2** 插件、**bsk 0.4.1** CLI／daemon 和 **BrowserSkill 0.4.1** Chrome 扩展，使用协议 **1.8**；功能或协议升级需按配套基线执行；当前插件展示资源更新沿用 0.4.1 CLI 与扩展，中文插件列表中显示为 **BrowserSkill · 浏览器自动化**。保留原来的 bskPath、独立的 bskHome、暂存目录、恢复目录与端口，并在扩展中连接同一端口。官方原版已提供上传下载；此包额外保留工作区／暂存目录限制、持久回执和重复请求去重，直接换成市场原版不会保留这些定制。本机原生安装、重载和合成浏览器操作检查已通过。CAT 编辑和工作副本不要求浏览器连接。版本与升级步骤以 [BrowserSkill 集成说明](integrations/browser-skill/README.md) 为准。

## 开始第一项任务

在 DSH 侧栏点击 **添加工作区 → LA 工作区 · 本地化项目**，选择目录、源语言和目标语言，创建后即进入 Linguist 通用会话。已有工作区也可从左侧 Linguist 页面新建项目。然后导入一份文件。XLSX 需确认工作表和列映射；Phrase split/master 同批选择。

新建会话时，在原生模式菜单选择 **Linguist**，输入框上方显示 **通用／译者／审校／校对** 岗位菜单，以及 CAT／工作副本／浏览器方式。工作区只有一个活跃 LA 项目时自动关联；有多个项目时明确选择。首次发送前可修改岗位、项目和工作方式；发送后换岗位会新开会话，原会话保留。其他 DSH 模式不显示这组控件。

例如：

> 审校这批中译英文本，逐条检查原文和当前译文，注意技能名称、语气、数字和标签。按要求修改，并汇总仍需我确认的问题。

> 只检查术语不一致和占位符问题，先列出结果，不修改译文。

**通用、翻译、审校、校对**四个岗位均保留 DSH 通用工具和用户选择的权限。审校默认覆盖已确定的完整工作范围。CAT 选区按需点击“附带 CAT 选区”，随该条消息冻结发送。

通用岗位负责统筹，正式翻译从开工即交给翻译岗位；正式翻译交付前必须由独立审校任务检查。交接区分客户要求、参考资料和模型建议，审校员可质疑前序译稿。各岗位按本批实际用途核对术语、风格和必要的文化事实，重要查证保留来源；译者自检与独立审校分别报告。这些是岗位执行要求，不保证模型每次都能正确判断，重要交付仍需人工复核。

审校时，当前译文写回 TM 后形成的 100%／101% 自匹配不能作为独立质量依据；需核对来源、Key、任务、更新时间和审批依据，来源不明时按参考处理。

Agent 可按连贯内容成组工作，使用已读快照提交修改与明确审过的范围；版本和写入回执由软件关联。工作副本可与绑定项目的 CAT 当前成果接续，并通过 `deliver` 生成经回读验证的原格式文件。格式不兼容时，Agent 可使用已有工具、任务脚本或适配器修复，在副本验证后继续。操作与恢复方式见 [工作副本与浏览器](QUICK_START.md#工作副本与浏览器)。

变量默认与原文保持一致。若项目规范明确要求某条译文补入变量，可让 Agent 引用规范原文、核对同批次关联原文后登记该句段的确切变量例外，也可删除登记恢复默认校验。例外绑定句段、原文和目标语言，用于写回、QA 及交付预检；不会自动扩散到重复句、其他批次或项目。原译和 TM 命中本身不能授权例外；这项登记也不批准补充时长等普通文字信息。

常用编辑、参考资料、备份和恢复见 [使用指南](QUICK_START.md)。

四岗位共用一份专业判断标准，按文本用途检查机制、人物、语境和项目要求。同文、同源异译与异源同译提示先标为待复核，确定的变量和标签错误仍按缺陷处理。默认不按中英字符长度比例报警；实际长度限制需结合项目要求检查。CAT 上下文可按需提供最多两组人工审定的相关案例；目前案例覆盖中译英的机制、UI、物品和对白。案例用于类比，不能替代当前项目事实或人工质量判断。

## 文件与限制

| 用途 | 当前范围 |
| --- | --- |
| CAT 待译导入与原生导出 | 通用 XLIFF、Phrase MXLIFF、SDLXLIFF、memoQ MQXLIFF、CSV/TSV、受支持的 JSON 结构、已映射 XLSX、Phrase 双语 DOCX |
| 翻译记忆 / 术语资料 | TMX、SDLTM、TBX、SDLTB、CSV、已映射 XLSX；按资源类型导入 |
| 参考正文抽取 | PDF、DOCX、XLSX、Markdown、TXT；图片可作为视觉参考，其他保留原件的格式可能无可读正文 |
| 原稿预览 | 文本、图片、PDF；DOC/DOCX、PPT/PPTX 交给 DSH 原生 PDF 排版预览，XLS/XLSX 交给 DSH 原生只读表格查看器 |

在 CAT 的资料、批次原件或参考导入候选中点击预览，即在当前会话的 DSH 文档标签中打开。插件给宿主提供带原扩展名的只读暂存副本，原稿不变；副本一小时后可回收，过期后重新点击预览。Office 查看器不能编辑 CAT 译文。普通 Word 文档作为参考资料读取，不承诺任意 DOCX 的 CAT 无损往返。

- **单文件接收上限 512 MiB（536,870,912 字节）**，普通批次和参考资源一致。一次最多选择 500 个文件。
- 每个文件分请求顺序上传，各请求的文件内容预算为 512 MiB；收齐后仍按同一业务批次导入，保留 Phrase 配对。整批合计可以超过 512 MiB。
- 接收上限不保证任意格式在该体积下都能快速解析。压缩包安全检查、抽取和预览采样仍存在；PDF、DOCX、Markdown 和 TXT 的参考正文抽取上限为 200,000 字符。
- 导入完成、确认重复或取消后释放无用暂存。待确认输入最长保留一小时；过期需重新选择文件。在途读取受到保护，重启后会回收过期孤儿。

**DSH 的接收与预览上限分开。** 原生默认 Word/PPT 输入上限为 50 MiB，Excel 为 16 MiB。需要大文件预览时，按[原生预览配置](CONTRIBUTING.md#原生预览配置)提高到 512 MiB；本插件不会静默修改宿主设置。该配置仍保留转换超时、解压体积和单元格上限，512 MiB 不代表任何文档都能快速渲染。

此前在 DSH 0.2.0-rc.2 复现过缺少默认行高的 XLSX 显示空白网格；当前宿主版本尚未复测此项。这类文件仍可导入 CAT 并使用批次语义预览查看源文和译文。

## 工作结果与数据

CAT 修改写入 LA 的项目库，原稿独立保存；导出产生交付副本。工作副本模式在 DSH 工作区中生成派生 JSON 工作稿，不能当作原生交付文件或平台已提交。浏览器模式通过 BrowserSkill 操作实际页面，外部提交需用户授权并核对平台结果。

macOS 默认数据目录为 `~/Library/Application Support/Linguist-Agent-DSH`。更新保留项目和设置，卸载插件不会自动删除项目目录。清理仅针对 LA 自己的暂存，不删除正式来源、数据库、备份或交付文件。

项目存储在本机，模型请求与浏览器、飞书等外部服务仍可能发送用户授权的内容。实际传输取决于使用的模型和工具；“本地存储”不等于完全离线。

通用岗位在 CAT 项目中可以委派专业子任务；不能将这一专用委派宣传为所有模式都同样支持。启动任务、模型生成结束、全量审校完成、导出文件和平台提交分别记录。
