# Linguist Agent

游戏本地化的翻译与审校助手，在 DeepSeek Harness（DSH）中使用。

整理项目文件、术语和翻译记忆，完成翻译、全量审校与校对；在双语 CAT 工作台中使用行内标签 chip、不可见字符、术语提示、用例检索和修改差异辅助编辑，处理 QA 问题并导出支持的文件。Phrase MXLIFF 支持原生粗体、斜体、下划线及其平面组合的富文本显示、格式码视图和选区格式编辑；工具条操作只修改草稿，可连同选区撤销、重做，运行时标签继续受保护。编辑辅助的开关、项目词典与真实长度约束见 [快速开始](QUICK_START.md#编辑辅助)。

**第一次使用：安装插件 → 打开项目工作区 → 说明要做的工作与配套资料。** 正式任务首次开工，LA 会核对稿件并建议工作方式；你还没选时会问一次是否使用 CAT。已有选择、续接任务或交给 LA 决定时直接继续。

## 安装

当前适配基线为 **官方 DSH 0.2.2-rc.3**，运行兼容范围为 `>=0.2.2-rc.3 <0.2.3-0`，开发与检查平台为 **macOS Apple Silicon**。范围内的小更新不会仅因版本号被禁用；接口变更仍需复查。本次构建的原生安装与加载状态需在 DSH 中确认；其他系统、宿主版本及真实客户平台任务尚未验证。

1. 打开官方 DeepSeek Harness，完成首次初始化与模型登录。
2. 确认 DSH 版本与上述基线一致。该版本已内置 LA 所需的自动化服务。
3. 在插件管理中选择维护者提供的 **linguist-dsh-plugin-1.7.0.tgz** 本地安装包，完成后选择“立即启用”；中文插件列表中显示为 **Linguist Agent · 游戏本地化**，点击条目可阅读包内详情，包含功能、开始使用、保存与兼容说明；详情语言跟随 DSH 界面语言，不支持的语言回退到英文。项目数据保留。由 1.3.4 或更早版本升级时，请在当前任务保存停稳后重启一次 DSH，移除旧 Agent 的额外工具结果裁剪；原会话可以继续使用。由 1.3.5 升级可直接热应用。
4. 打开左侧 **Linguist**。首次使用会自动建立数据目录与持久安装标识，无需填写作者路径；已配置的目录、标识和通知设置继续使用。

截至 2026-10-02，仓库提供公开源码，没有 GitHub Release 安装包；本轮产物在本机生成。构建方式见 [开发说明](CONTRIBUTING.md)。

浏览器任务使用官方 BrowserSkill CLI／MCP 和配套 Chrome 扩展，通过 DSH 官方 MCP client 接入，可用 Fishquito 面板管理。CLI 使用官方正式发行版并保留自动更新，扩展由 Chrome 商店更新，安装与配置见 [BrowserSkill 集成说明](integrations/browser-skill/README.md)。

## 开始第一项任务

在 DSH 侧栏点击 **添加工作区 → LA 工作区 · 本地化项目**，选择目录、源语言和目标语言，创建后即进入 Linguist 通用会话。已有工作区也可从左侧 Linguist 页面新建项目。选择 CAT 后，LA 用工作区原件准备受管理的副本、关联资料，并返回段落、标签与锁定检查结果；原稿不变。也可以手动导入。XLSX 需核对工作表和列映射；Phrase split/master 一起提供。

在 Linguist 主页选择工作区、岗位和工作方式，再点击项目卡片的 **新建 LA 会话**，会话自动绑定该项目和工作区。下方 **项目会话** 按所选工作区显示，供继续旧任务。也可从 DSH 新建会话的原生模式菜单选择 **Linguist**，使用输入框上方的岗位、项目和工作方式菜单。工作区只有一个活跃 LA 项目时自动关联；有多个项目时明确选择。首次发送前可修改岗位、项目和工作方式；发送后换岗位会新开会话，原会话保留。其他 DSH 模式不显示这组控件。

例如：

> 审校这批中译英文本，逐条检查原文和当前译文，注意技能名称、语气、数字和标签。按要求修改，并汇总仍需我确认的问题。

> 只检查术语不一致和占位符问题，先列出结果，不修改译文。

**通用、翻译、审校、校对**四个岗位均保留 DSH 通用工具和用户选择的权限。无需先导入 CAT，就可以直接询问游戏本地化问题，或交代文件、线上任务；需要专业子任务时按实际职责选择岗位。审校默认覆盖已确定的完整工作范围。CAT 选区按需点击“附带 CAT 选区”，随该条消息冻结发送。

通用岗位负责统筹，正式翻译从开工即交给翻译岗位；正式翻译交付前必须由独立审校任务检查。交接区分客户要求、参考资料和模型建议，审校员可质疑前序译稿。各岗位按本批实际用途核对术语、风格和必要的文化事实，重要查证保留来源；译者自检与独立审校分别报告。这些是岗位执行要求，不保证模型每次都能正确判断，重要交付仍需人工复核。

CAT 自动上下文按当前匹配限额提供普通 TB 译名、备注和已登记的来源，保留术语原有状态；普通参考不会自动变成强制用法。已选中的术语正文超过响应预算时沿现有分片续读，不要求逐词确认。旧项目中未保存逐条来源的术语，可重新导入原术语库以关联来源；无法核实的来源不会猜测。

点项目卡片上的 **任务组**。可按来稿或版本建组，在组内导入批次、打开本组资料或新建 LA 会话。两个任务组可以接收同一份原稿，各自编辑和导出。需要保留现有译文、锁定和修订时，在任务组页移动原批次。项目会话的 CAT 工作台先选任务组，再选工作批次；“全部批次”和左侧导航都只显示当前组。从任务组新建的会话固定在该组。

从 **Linguist 主页 → 项目卡片 → 项目资料** 可以查看、添加、替换和移除项目原件，编辑用途及适用范围，查看读取状态和提示，不用先打开 CAT。GUI 与 Agent 管理同一份资料；已有 CAT 导入的有效 TM／TB 和上下文原件也会显示。项目共用资料也用于普通问答、文件和线上任务。LA 登记实际提供的 TM／TB、Checklist／SG、例句、Query 和反馈；两列术语表或普通文字文档也可用，不要求补齐状态、模块等字段。普通消息直接进入对话。问题涉及项目术语、历史译法或客户要求时，LA 在答复前按当前范围查原件。普通查词使用文字和 TM／TB 匹配，按意思找例句时使用本地语义模型。正式审校按本批原文准备相似句，随稿附上适用要求、按文字命中的背景记录及出处。独立 Reviewer 可针对疑点再按含义查项目资料。文件不变时复用抽取与检索缓存，变化时刷新，不增加逐条查询或回执。没有提供的资料不会凭空补全。

人工确认或岗位登记成功的当前译文会写入项目 TM，并记录任务、句段、操作者和确认阶段；阶段确认不等于客户批准。审校时，本任务形成的自匹配会标记，不能作为独立质量依据；来源不明时按参考处理。

Agent 可按连贯内容成组工作；CAT 读取的版本由软件关联，实际审完全范围后可集中声明，不必抄录快照编号。CAT、文件和线上快照均可准备本批双语及参考材料；指定的 TM／TB 与旧项目资产分开处理。工作副本可与绑定项目的 CAT 当前成果接续。本机已安装 MemSearch ONNX 环境并缓存 BGE-M3 INT8 模型时，三种方式共用语义分组与缓存；关联原文、当前译文和必要依据直接附入普通审校材料，不每 50 条取一次资料。相似只是审校线索，不计入 QA 错误数。绑定项目的工作副本可通过 `deliver` 生成经回读验证的原格式文件；无项目的文件任务可使用已有工具或脚本交付。全局显示／检索偏好和缓存管理位于 **DSH 设置 → Linguist**。操作与恢复方式见 [工作副本与浏览器](QUICK_START.md#工作副本与浏览器)。

变量默认与原文保持一致。若项目规范明确要求某条译文补入变量，可让 Agent 引用规范原文、核对同批次关联原文后登记该句段的确切变量例外，也可删除登记恢复默认校验。例外绑定句段、原文和目标语言，用于写回、QA 及交付预检；不会自动扩散到重复句、其他批次或项目。原译和 TM 命中本身不能授权例外；这项登记也不批准补充时长等普通文字信息。

常用编辑、参考资料、备份和恢复见 [使用指南](QUICK_START.md)。

四岗位共用一份专业判断标准，按文本用途检查机制、人物、语境和项目要求。同文、同源异译与异源同译提示先标为待复核，确定的变量和标签错误仍按缺陷处理。默认不按中英字符长度比例报警；实际长度限制需结合项目要求检查。CAT 上下文可按需提供最多两组人工审定的相关案例；目前案例覆盖中译英的机制、UI、物品和对白。案例用于类比，不能替代当前项目事实或人工质量判断。

## 文件与限制

| 用途 | 当前范围 |
| --- | --- |
| CAT 待译导入与原生导出 | 通用 XLIFF、Phrase MXLIFF、SDLXLIFF、memoQ MQXLIFF、CSV/TSV、受支持的 JSON 结构、已映射 XLSX、Phrase 双语 DOCX |
| 翻译记忆 / 术语资料 | TMX、SDLTM、TBX、SDLTB、CSV、已映射 XLSX；按资源类型导入 |
| 参考正文抽取 | PDF、DOCX、XLSX、Markdown、TXT；图片可作为视觉参考，其他保留原件的格式可能无可读正文 |
| 原稿预览 | 文本、图片、PDF；DOC/DOCX、PPT/PPTX 交给 DSH 原生 PDF 排版预览，XLS/XLSX 交给 DSH 原生只读表格查看器 |

审校材料可为本批 XLSX 和 PPTX 提取内嵌图片并保留工作表位置或幻灯片页码，结果缓存在工作区；图片仍需由 Reviewer 实际查看。SDLXLIFF 的分段可按原始单元连续阅读，唯一匹配的原表位置和相关图片随材料提供；跨段说话人标签的空格异常作为待判断提示。PPTX 图片不包含幻灯片上的文字及其他版式，必要时应查看原幻灯片。

在 CAT 的资料、批次原件或参考导入候选中点击预览，即在当前会话的 DSH 文档标签中打开。插件给宿主提供带原扩展名的只读暂存副本，原稿不变；副本一小时后可回收，过期后重新点击预览。Office 查看器不能编辑 CAT 译文。普通 Word 文档作为参考资料读取，不承诺任意 DOCX 的 CAT 无损往返。

- **单文件接收上限 1 GiB（1,073,741,824 字节）**，普通批次和参考资源一致。一次最多选择 500 个文件。
- 每个文件分请求顺序上传，各请求的文件内容预算为 1 GiB；收齐后仍按同一业务批次导入，保留 Phrase 配对。整批合计可以超过 1 GiB。
- 接收上限不保证任意格式在该体积下都能快速解析。压缩包安全检查、抽取和预览采样仍存在；资料页导入的 PDF、DOCX、Markdown 和 TXT 参考摘要上限为 200,000 字符。由 Agent 登记的共用资料原件按完整可抽取正文建立索引，解析限制或缺失正文会提示；图片仍需实际查看。
- 导入完成、确认重复或取消后释放无用暂存。待确认输入最长保留一小时；过期需重新选择文件。在途读取受到保护，重启后会回收过期孤儿。

**DSH 的接收与预览上限分开。** 原生默认 Word/PPT 输入上限为 50 MiB，Excel 为 16 MiB。需要大文件预览时，按[原生预览配置](CONTRIBUTING.md#原生预览配置)提高到 1 GiB；本插件不会静默修改宿主设置。该配置仍保留转换超时、解压体积和单元格上限，1 GiB 不代表任何文档都能快速渲染。

此前在 DSH 0.2.0-rc.2 复现过缺少默认行高的 XLSX 显示空白网格；当前宿主版本尚未复测此项。这类文件仍可导入 CAT 并使用批次语义预览查看源文和译文。

## 工作结果与数据

CAT 修改写入 LA 的项目库，原稿独立保存；导出产生交付副本。工作副本模式在 DSH 工作区中生成派生 JSON 工作稿，不能当作原生交付文件或平台已提交。浏览器模式通过 BrowserSkill 操作实际页面，外部提交需用户授权并核对平台结果。

macOS 默认数据目录为 `~/Library/Application Support/Linguist-Agent-DSH`。更新保留项目和设置，卸载插件不会自动删除项目目录。清理仅针对 LA 自己的暂存，不删除正式来源、数据库、备份或交付文件。

项目存储在本机，模型请求与浏览器、飞书等外部服务仍可能发送用户授权的内容。实际传输取决于使用的模型和工具；“本地存储”不等于完全离线。

通用岗位可在 CAT、工作副本和浏览器方式下委派专业子任务。启动任务、模型生成结束、全量审校完成、导出文件和平台提交分别记录。
