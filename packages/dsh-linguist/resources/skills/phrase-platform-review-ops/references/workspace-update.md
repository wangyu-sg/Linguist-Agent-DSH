# 工作区定制说明的更新边界

本产品随包提供只读的通用平台技能（`phrase-platform-review-ops` / `weloc-platform-ops`）。**不要**编辑已安装插件包，也**不要**把私有客户 URL、账号信息、项目映射、客户正文或临时回执提交到 LA-DSH 产品仓库。

## 项目专用信息放在哪里

- 客户平台入口、项目/作业映射、语言对与特定客户授权要求（例如某项目是否保持 `Accepted`、不导出或不回填），应保存在对应项目工作区的项目文档中（如工作区 `AGENTS.md`、项目导航、批次说明与台账）。
- **不要**在 `~/.dsh/skills/` 或工作区 `.dsh/skills/` 创建同名的 `phrase-platform-review-ops` 副本存放项目说明——DSH 的 Skill 发现机制会用用户/工作区同名目录**遮蔽**插件随包维护的新版通用技能，导致后续版本修复和规则更新无法生效。

## 确需更新或临时覆盖时

1. 仅在用户明确要求为特定项目建立工作区 Skill 覆盖、且确认不会与后续随包更新冲突时，才在工作区 `.dsh/skills` 维护；不要在普通回填任务中热改通用 Skill。
2. 修改前先备份原文件；调整后通过 DSH 原生 Skill 列表核对实际生效的路径、版本与正文。未观察到新版正文实际进入模型请求前，只报告文件已更新，不宣称新规则已经生效。
3. 发现可复用的通用平台界面变化（例如菜单位置变更、导出限制）时，整理脱敏后的适用版本、界面现象与判断方法再合入随包参考，客户专属内容仍留在各自工作区。
