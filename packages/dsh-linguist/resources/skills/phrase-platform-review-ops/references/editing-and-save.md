# Phrase 输入、标签、保存与状态流转

## 1. 写前核对与唯一终稿

- **唯一批准终稿**：开始回填前，先在批次材料中为每个可写键确定唯一终稿；若多个草案字段或版本不一致，先按批准记录核清，未确定的键暂缓写入。
- **紧邻输入的三重比对**：每次写入前必须在执行端紧邻输入读取并核对：所属 **Job**、**流程阶段**、**稳定段 ID**、**完整 Source**、**实时 Target**、**锁定状态**、**当前步骤确认状态** 与 **原生标签/换行结构**。
  - 实时 Target 已等于批准终稿：跳过写入，核验结构与状态后计入“原已一致”。
  - 实时 Target 等于批准底稿且未锁定、符合本批授权：允许执行写入。
  - 实时 Target 为第三种译文、Source 已变或处于锁定/授权外状态：停止写入该键并登记冲突/阻塞，保留现场，不覆盖他人修改。
- **身份漂移处置**：若写入过程中发现行身份漂移或改错行，立刻停止本组后续写入，同时读取预期键与误改键的实时值；仅在确认实时值确属本轮刚刚写入且在权限内时才定向恢复，不盲用通用 Undo 撤销无关中间变更。

## 2. 编辑方法与原生标签、空格、换行保护

- **不要假写入**：修改静态展示 DOM（`.twe_target` 下的 `span` 文本或样式）不会进入内部文本模型与保存队列。
- **纯文本与含标签/格式句段分开处理**：
  - **纯文本**：使用宿主浏览器工具支持的原生聚焦输入或原生剪贴板替换即可。
  - **含标签、内联格式或变量**：纯文本剪贴板拷贝与粘贴可能丢失或破坏原生标签 chip，不得把纯文本剪贴板当成含标签译文的往返载体。
  - **标签编号不是运行身份**：显示编号（如 `{1}`、`1`）与底层配对、属性、作用范围及运行时占位不同；相同高亮颜色的芯片也可能代表不同标签。**绝不能**用手打字面 `<color=...>` 或 `{variable}` 替换原生芯片。
  - 若标签顺序不变，优先仅编辑发生变化的纯文本片段，让原生标签留在原位（按偏移修改多段时从后往前改，防止前序偏移失效；注意原生芯片与 Unicode 字符长度不一定等于 JS `.length`）。需要插入或重排结构时，使用编辑器原生插标签动作（观测版为 `F8` 插入下一个缺失标签）。
- **不可见字符与长度边界**：
  - 编辑器用独立伪元素槽位渲染普通空格、全角空格、NBSP 与回车符装饰；对比前后文本时必须取真实文本片段并区分全半角空格、NBSP 与硬换行，不以折叠空白后的 AX 文本作判断。
  - 硬换行沿用项目要求（观测版使用 `Shift+Enter`）；若项目规范需要同时保留硬换行与字面 `\n`，按原始结构保留。
  - 观测版构建代码在保存与确认前会对原文/译文序列化字符串检查 `8,191` JS `.length` 上限。

## 3. 快捷键与浏览器工具按键差异

- 先核实当前 `ego-browser` / 宿主输入命令如何区分“按键组合”与“字面输入”：部分文本填入指令会把 `Meta+A` 当作普通字符输入，应按当前指南使用明确的快捷键命令或菜单控件。
- 常见快捷键参考（需结合当前系统及工具确认一次后复用）：
  - `F8`：插入下一原生标签；`Shift+Enter`：插入硬换行。
  - `Cmd/Ctrl+Enter`：确认当前句段；`Cmd/Ctrl+Shift+Enter`：取消确认；`Cmd/Ctrl+G`：跳转句段；`Cmd/Ctrl+K`：TM/TB 搜索；`F9`：QA 检查。
  - 注意 `Cmd/Ctrl+D`（删除译文）与 `Cmd/Ctrl+数字`（采用第 N 条候选）容易被浏览器书签或切换标签快捷键抢占，优先使用菜单按钮或已核实有效的按键方式。

## 4. 保存队列、持久化核验与异常恢复

- **切段保存机制与误判风险**：
  - 在构建代码中，切到另一句段或开始多选时会把旧段排入单段异步保存队列，且在构造待发送快照时即清理编辑器本地脏标记，随后异步请求落盘；`beforeunload` 仅作未保存离开确认，不能保证关页前一定落盘。
  - 因此：**页面文本变化、`dispatched`、旧的 Saved 图标、或与当前句段无关的 2xx 响应，均不足以证明本次修改已持久保存。**
- **取得可靠保存依据**：
  - 观察到可明确归属本次修改的保存回执后入账；若未观察到可靠回执，在没有未保存脏段的边界，执行一次安全的页面重载/重进或导出双语 MXLIFF，按 `Job + 稳定段 ID` 回读比较终稿文本、标签配对、不可见字符和状态，再登记已保存（不必每写一行就重载）。
- **超时与保存失败恢复**：
  - 遇到请求超时或保存报错，切勿立即重放或 Undo：实际修改可能已落盘到服务端。
  - 先以只读方式（读取/重载/导出）核对受影响键：已落盘的项记入已成功前缀；确认上一笔操作已 settle 且写前检查再次通过后，才从第一条未决键继续重试。若多次有界核对仍无法确认状态，保存检查点并停下，不留后台写入并发。
  - 同一作业同一时间只允许一个写入者（单开与合开视图重叠也算同一作业）。收到用户停止指令后立刻停止派发下一条写入。

## 5. 重复句联动、句段确认与 Job 状态边界

- **重复传播**：编辑阶段可能自动把当前改动传播到同源重复句（受项目设置对重复与锁定行的规则控制）。写入或确认重复组前，须核对全部受影响成员是否在本次授权范围内；若可能波及授权外句段或锁定项，暂停该组并说明范围。
- **编辑重置确认状态**：修改一条当前阶段已确认的句段，通常会将其自动重置为未确认。若本批任务只回填 Target 且要求保留现有确认状态，须避开会重置确认的操作或在动手前把影响交代清楚。
- **句段确认 vs Job Accepted / Completed / Delivered**：
  - 流程阶段各自独立：不要用前一流程的确认状态代替当前步骤确认。
  - 确认整批或指定范围前：先完成译文写入与独立 TM 证据采集，清除筛选，核对原生多选范围完全落在授权可写段内，再执行**句段确认**，随后回读当前流程阶段确认计数与项目页作业状态。
  - 若当前批次授权明确要求保持作业 `Accepted`（不自动完成或交付），确认句段后**绝不要**点击成功提示浮窗中的完成作业（Completed）链接。不同客户/批次授权各异，上述限制仅适用于已声明的当前任务条件。
