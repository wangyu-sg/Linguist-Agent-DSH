# Phrase 参考面板、批注与 QA

> **适用条件**：以下异步刷新与界面机制基于 Phrase Web Editor（构建 `26.23.11`）观察及实际 QA/TM 作业总结；不同项目配置与后续版本可能调整面板权限与规则，使用时以当前页面可见状态为准。

## 1. 右侧辅助区与异步面板归属

- 右栏提供八个辅助面板：**CAT**（TM / TB / MT / 不可译 / DNT）、**语料库搜索**、**QA**、**历史译文**、**更多语言**、**备注**、**LQA**、**资源**；底部区域提供 **上下文注释**（以及格式支持时的 **文内预览**，后者按已加载内容覆盖，可能只是局部片段）。
- **CAT 面板的异步刷新与竞态**：
  - 构建代码中，CAT 面板将 TM、TB、MT、不可译与 DNT 分开请求并按稳定段 ID 存入内存缓存，只有响应匹配当前展示的段 ID 才会更新界面；项目配置也可决定并发查 TM/MT 或按分数条件再查 MT。
  - **真实作业观察（必须警惕）**：在选中一条已有译文的句段时，面板曾先显示「该句段无匹配或建议」，数拍之后同一段才列出两条明确标为 `TB` 的术语结果。
  - **归属规则**：切段后采集面板信息，必须同时记录**当前选中段 ID**与**面板刷新完成依据**。列表非空或首个候选还挂在界面上，不足以证明属于新选中的段；相反，旧源文模糊匹配本来就可能与当前源文不完全相同，应依据刷新与选中证据归属，而不是强制全文相等。如果区分不出仍在加载、确实无结果还是查询失败，应分别登记或标为未核实，不得把上一段候选记入当前段。

## 2. 客户 TM 与 TB 查证尺度

- **覆盖分母与结果分类**：覆盖分母由本批任务说明决定。每个应查句段应记录：Source 身份、指定客户库来源、刷新/查询依据、适用候选及裁定。旧面板残留、来源不明文本、仅 TB 命中均不可冒充客户 TM 查证完成；确实查清且无适用匹配是可记录的有效结果。
- **精确查词与上下文检索**：
  - 在 Phrase TM/TB 搜索框执行精确查询时，使用**英文半角（ASCII）双引号**，例如 `"登场"`，或使用编辑器自带的 Exact search in TM/TB 动作。
  - 单一短词无法消除歧义时，用有辨识度的短语或完整 Source 搜索，结合语料库搜索与资源面板核对库名、读写权限及版本。
- **排序、高分与批准状态的区分**：
  - 首条候选常因匹配分高排在最前，但很可能是较早导入的旧译。裁定前核对匹配原文与译文、所属指定客户库、适用语境、批准状态及可见的导入/修改时间。
- **禁止以本轮自匹配冒充独立客户依据**：
  - 当项目配置了可写 TM 且允许确认写入时，在平台确认译文可能立即把当前译文写入 TM（即时 QA 告警或导入/预翻配置可能影响写入）。
  - 独立 TM 证据应在确认之前完成采集；确认之后读到的 `100%` / `101%` 同文匹配若源自本轮写入，**不得**作为支持该译法的独立客户依据，更不可静默替换确认前采到的原始证据。

## 3. 备注（Comments）与人工 LQA

- 备注支持整段、选区和多段批量会话（修改或回复批量子备注会影响关联成员）；LQA 附着于特定工作流程步骤与评估配置。
- 构建代码中，备注和 LQA 首次加载后由独立 Worker（`conversationsMapperWorker`）映射对话到句段（精确 ID 缺失时存在同组或相邻组回挂规则），另有 `60 秒` 轮询与超时清理。
- 跨修订后选区锚点可能移位或失效。涉及历史备注的句段，回填或复核时应核对实际锚点所在侧、上下文与当前版本，再决定回复或标注解决。

## 4. 自动 QA 与覆盖边界

- **即时 QA vs 手动 QA**：
  - **即时 QA**：确认单段时按项目设置触发，告警或阻塞可能阻止写入 TM。
  - **手动 QA**：文档面向整个 Job；构建代码会先为当前段排保存再排 QA。若只检查了部分任务，或整批检查后又修改了译文，QA 状态会变为 `Incomplete`。
- **完整加载 QA 列表**：
  - 记录运行范围（全批/选中/已改段）、可见筛选及是否隐藏已忽略项。点击「加载更多（Load More）」后，等待新告警条目/数量增长或明确的结束态再判断；按钮短暂消失但列表未Settled、或内容无变化时不要盲目连点。
  - 表格可能把同一位置的多个告警合并显示序号单元格，观测样本中行元素曾分别携带 `data-id` 和 `seq-no`；关联告警必须取各自稳定段 ID，不可只按展示位置匹配。未证明覆盖全量时，报告为“已读取当前显示的 N 条”，不虚报全批总数。
- **单开与合开视图的 QA 差异及处置**：
  - **已观察风险**：同一批作业在单开与合开视图下，部分告警的显隐或点击「忽略/略过」的持久化表现可能不一致（合开列表点击忽略后，切回对应单一作业仍可能处于未忽略状态）。
  - **诊断与平台动作分开**：
    - 确认属实并修复：记录修复前后版本，对受影响范围重跑 QA 验证告警消除。
    - 确认为误报：只有获授权时才在平台执行忽略（并在对应单一 Job 核实已保存）；未获忽略授权时，仅在报告中登记为保留误报并附具体条文或双语依据，绝不为了列表清零而批量忽略。
    - 真实问题按需保留或超出本批范围：分别记为已知保留项或范围外项，不冒充已解决。
  - 报告中始终区分初始 QA 数量、修改后复查数量、已忽略数与未核实项。
