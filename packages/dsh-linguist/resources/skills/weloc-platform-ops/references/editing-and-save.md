# WeLoc 输入标签、保存机制与并发风险

> **观察范围说明**：以下行为基于特定现网版本 WeLoc 前端观察（Tiptap / ProseMirror + CMS/TMS 双路径 + `weloc_db_1` 临时存储），供理解输入、保存风险与恢复原则使用；实际写回仍以当前页面现场反馈与本批授权为准。

## 1. 编辑态挂载、`setContent` 重绘与输入保护

- 激活 `TargetText` 后挂载的 Tiptap / ProseMirror `EditorView`，在非 IME 组合输入态触发 `update` 后，会重新序列化文档、重新识别标签并调用 `commands.setContent`。
- **重绘副作用**：`commands.setContent` 可能改变当前焦点位置、文本选区以及行内批注装饰（Decoration）。
- **作业要求**：每次向编辑器输入内容后，必须依据编辑器当前实际状态与文本内容接续，不要在重绘后继续套用修改前缓存的选区坐标或旧 DOM 节点。避免直接向静态 `div.text.parent` 写入。

## 2. 标签识别与空白/换行规范化

- **两种标签保护机制并不等价**：
  - **通用标签**：覆盖尖括号 `<>`、花括号 `{}`、方括号 `[]`，主要经 `WelocTagView` 封装保护。
  - **项目自定义标签**：支持字面量或正则表达式配置，主要经 `Decoration.inline` 及删除拦截实现。
  - **高风险点**：两者在页面上的高亮颜色可能看起来完全一致，但底层保护机制不同；在解析嵌套括号时，机制可能只保留最内层的非空标签。务必检查当前项目/页面的 `CustomTagProtection` 实际配置状态，不能仅凭高亮颜色或括号数判断标签安全，保留真实的原始占位符与文本结构。
- **剪贴板与空白换行**：
  - 剪贴板粘贴主要读取 `text/plain`，标签在进入编辑器后再行识别；编辑器自带的复制标签功能则按当前规则插入。
  - 换行归一化受 `disable_newline_normalize` 设置影响，且部分内部宽空格会被还原为普通空格。核对批注引用、变量或回填结果时应保留这些原始字符差异，不要仅因肉眼“看起来一样”就当作相等或强行抹平差异。

## 3. CMS 与 TMS 保存路径、40 秒轮询与本地存储

- **CMS 模式（CMSRnd / CMSOps 等）**：
  - 失焦（blur）通常**仅更新前端表格视图、`CMSDraftRows` 与本地存储**，并没有发往服务端保存。
  - 真正的服务端保存通常触发于点击 `Confirm`（确定译文）、执行 QA 或组件卸载路径；而**组件卸载绝不是可靠的关页保存承诺**，因此绝不可依赖刷新或关闭标签页来当成正常保存。
  - 在需要服务端持久化且有授权时（例如之前观察到的按该批正常流程点击「确定译文」后重开才保留的场景），必须先明确本批是否授权确认/触发对应路径，**绝不能为了保存草稿擅自点击确认或推进客户阶段**；无权确认的草稿状态应如实记录为本地草稿及未提交风险。
- **TMS 模式**：
  - 失焦即触发服务端保存（源码按每片 300 条处理属于前端分片实现细节，不要求人工每次强行凑满 300 条）。
- **40 秒轮询覆盖风险**：
  - 该版本存在约 40 秒的定时轮询，仅在特定选区条件下运行；遇到当前正在编辑的行可能提前退出循环，但其余非编辑行可能被服务端版本直接替换，导致未提交的 CMS 本地草稿被覆盖丢失。
  - **操作原则**：存在未提交本地草稿时切勿盲目刷新页面；保留已核实修改记录与实际保存状态，也不要为躲避轮询而自建高频定时回填器。
- **保存失败与恢复**：
  - 保存或改状态失败可表现为行上的 `Save_Failer` / `Modify_Status_Failer` 与错误提示，页面通常自带重试入口。先核查具体错误信息、当前界面稿与服务端重读值再决定是否重试；不要假设平台内置了自动离线补传或指数退避。
- **IndexedDB 与内存草稿定位**：
  - 浏览器本地 `weloc_db_1`（IndexedDB，按标签页分别建 Store，部分场景退回内存存储）仅属于临时工作态缓存，**不是用户或项目可依赖的正式备份**。遇到异常先保留现有修改稿，绝不把清空整份数据库或清除浏览器 Profile 写成常规排错步骤。

## 4. 快捷键冲突与操作边界

- **快捷键风险**：该观察版本记录了 `Cmd/Ctrl+D`、`Cmd/Ctrl+Enter` 等快捷键与误清空译文、确认后下一行未获得编辑焦点，以及与浏览器/macOS 宿主快捷键抢占的相关风险。优先根据当前界面实际可见控件与真实焦点判断和操作，不假设某组快捷键在当前环境必然有效。
- **阶段与权限边界**：保存草稿、运行 QA、句段确认、写评论与最终提交各自独立且具有不同服务端后果。只执行当前批次明确授权的动作；回填并确认落盘后，通过安全重读/重开或导出核对实际保留结果再交接。
