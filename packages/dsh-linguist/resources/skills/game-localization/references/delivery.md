# Excel 交付表

每次正式翻译、审校或校对收尾，使用 `linguist_delivery_report` 生成对应的 Excel。翻译用 `kind: "translation"`。审校、只报告的审校、校对和润色用 `kind: "review"`，范围写清实际工作。独立审校随正式翻译进行时，由各阶段分别填表。普通咨询、进度回复和中间保存无需填表。

先使用实际读过、保存或核验的结果编写工作区内的 UTF-8 JSON，再调用工具，传 `kind` 与工作区相对路径 `dataPath`。使用返回的 `path` 将 Excel 连同稿件交接或交给用户。生成失败时修正具体字段；工作和交付状态分别报告。导出、回填、平台确认和提交仍按各自授权及实际结果处理。

必填表头为 `task`（任务）、`languagePair`（源语 → 目标语）、`baseline`（实际底稿文件／版本）、`version`（本轮版本／日期）、`collection`（收录口径）、`scope`（实际完成范围，写清数量、边界和未决范围）和 `items`。收录口径可以是「逐段全量」「指定范围」，或翻译的「仅决定项与未决」、审校的「仅改项与未决」。审校完成且无改项时，可以填写实际范围，并按「仅改项与未决」提交空 `items`。

- **明细 `items`** 每项填写 `location`（可回到原稿的句段定位）、`source`（完整原文）、`status`。审校另填 `draft`（完整原译）；底稿确为空时填空字符串并说明。翻译的「定稿」和「保留原文」填写 `final`，「保留原文」须与原文一致。审校只有「采用终稿」填写 `final`，「保留原译」留空。待确认、待核术语（翻译）或待验结构都留空终稿，候选写进 `reason`。修改或暂缓的项填写 `reason`（理由）与 `evidence`（可核实出处），普通对应关系可引用本行原文。按需添 `questionId`（对应待确认页）和翻译的 `note`（备注）。
- **待确认 `questions`** 有成组问题时填 `id`、`affected`（影响范围）、`question`、`evidence`（已知依据／缺口）、`status`（草稿、已发待答、已答待复核、已结案之一），按已有信息填 `answer` 和 `next`。同一问题用同一编号。单条疑问可直接写在明细理由中。
- **历史对照 `history`** 有实际 TM 或旧稿争议时填 `location`、`source`（历史原文）、`target`（历史译文）、`reference`（来源及记录定位）、`relation`（匹配关系）、`decision`（本次取舍），有版本信息时填 `version`。
