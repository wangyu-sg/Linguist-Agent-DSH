# 工作区维护标准

用户说“接手”并给出名称或编号时，这就是查找批次的线索。先用 `glob`（`pattern: "*"`）列出工作区根目录，用 `read`（`file_path`）打开已有项目导航或批次索引，沿本批记录核对原件。入口缺失时用 `grep` 在相关目录查找这个标识。能确定批次就先交代已核实的结果和待补的证据。查过仍无法区分批次，或执行下一步确实需要用户决定时，再问具体问题。

所有 LA 岗位在建项、接手、收件、换版、移动或交付时，主动维护本次涉及的批次。普通咨询直接答复。受委派的岗位维护本批记录，涉及共用资料或其他组的变更交给主会话。

1. **收任务与接手。** 从工作区根目录已有的导航或索引，按客户使用的工具和批次标识找到本批。Finder 和 LA 的任务组或批次指向同一份工作。月份、客户任务号和跨工具入口沿用项目做法，目录按实际来稿建立。批次记录列出原稿、当前工作稿和进度，线上稿用平台工作项及最近核实的状态定位。保留客户原名和原包结构。已有索引就更新相应条目，缺少入口才在根目录建《项目导航》。整体搬迁先列旧址、新址、引用影响、搬前核对结果和搬后验证方法，按用户确认的范围执行。
2. **收资料与换版。** 查客户原件和说明，登记原名、位置、来源、版本、能决定的问题及适用批次。区分整份替换、局部补充和本批例外，归属或效力不明的标为待确认。临时材料随批保存。复用资料用 `linguist_prepare_project` 登记，同时更新磁盘索引。同范围换版用 `replaceResource` 指定旧条目，只有本组替代共用资料时在新条目上填 `replacesInherited`，新件读通后生效。覆盖会变动的共用文件前，为用过它的批次留可打开的旧版原件或平台版本链接。同一版本只存一份，各批引用。移动原件按 `lastReadSha256` 核对内容，并用 `listResourceFiles: true` 复查受影响范围。旧批若只剩版本号、指纹或部分依据，写清能复核到哪里以及缺什么。
3. **交接与收工。** 在本批原有记录写明日期、实际成果、未决项和下一步。正式译审把当前稿、实际交付件及 `linguist_delivery_report` 返回的相应 Excel 路径记在一起。多批共用一张表时，标出本批的页签或行标识。逐项核对本地完成、平台回填和平台确认。记录已核实的状态及出处。交接前从批次入口打开稿件、当时的资料和交付表，核对文件所载批次、版本及范围，再报告结果。

新会话不翻旧聊天，返回已核实的当前稿、当时用的资料、对应交付表和下一步。用 `linguist_inspect_delivery_report` 读取交付表，核对任务、底稿和范围。多批共表时传入批次号，结合台账核对页签或单元格。查实后补上遗漏的链接。只找到空白模板、现行文件的快捷方式或文件名时，写明还缺哪项证据。
