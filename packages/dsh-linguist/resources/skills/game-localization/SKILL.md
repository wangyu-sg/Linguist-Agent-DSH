# 游戏本地化作业

目标是玩家能理解、愿意读、在实际语境中成立的译文。准确性、自然表达、人物声音和技术正确性共同构成质量；术语与QA只能支撑判断。

## 正常流程

1. **定界与分工。**复用已知语言对、用途、当前批次/文件、预期产物和授权。General 按岗位规则统筹并从开工即委派正式翻译；专业执行者直接完成收到的职责，不重复委派。缺失信息足以影响结果时才补查，不要求用户重填已有简报。
2. **取得真正必要的依据。**使用有效项目基线、当前规则、相关术语/例句和必要上下文。必要规范尚未完整整理时不能只看增量；已完整有效则复用。先判断范围和版本，不按文件新旧或TM分数机械排序。
3. **连续语言判断。**按连贯内容和实际长度组织，读取分页不触发TM→写回→复读→确认关卡。T写目标语成品；E比较完整双语；P整体阅读目标语，对疑似误义回看源文。每阶段承担自己的完整质量责任。
4. **处理依赖而非停住整批。**影响当前含义或大量后续内容的疑点及时查询；其余显式必查按相关性成组补齐，相关完成/正式提交前闭环。独立内容继续，不因一个TM待查停止全部工作。
5. **收敛并提交。**候选只保留当前版本、实际裁定范围、必要修改和未决。用户已授权执行就用现有批量工具正式处理，不停在报告等催促；成功revision直接复用，冲突或未知只恢复相关项。完整结果由已有格式与数据能力组合，不每批重写解析器。
6. **按约定检查并收尾。**运行需要的QA/平台动作，分类实际问题与误报。模型或工具的自报状态不独立证明语言正确；分别报告语言裁定、必要查验、写入、Stage与平台状态。正常结果简短，完整明细留受控产物。

## 平台备注与查证

导出文件中的notes/context不保证包含线上Comments。开始时确认资料覆盖；优先在现有术语/TM核对中读取拟改项的备注。在线写回前须选中对应稳定ID，等待Comments面板刷新完成，核对当前Source/Target和实际备注；空图标或上一行面板不能证明无备注。未能读到时仅暂缓该项写回，不把全批每行都追加浏览器请求。纯文件任务使用实际交付的备注，平台资料缺失如实交接，不凭空创建线上检查。

客户指定译文须保留备注原文、作者、引用来源和适用字段/范围的依据；有实质冲突先列疑问，取得新的明确授权后才覆盖。普通建议不等于定稿，备注存在不等于锁定。同源其他字段是否适用，以真实关联ID和批准范围判断，不因中文相同就传播结论。

网页查证只用BrowserSkill当前公开能力。当前工具没有batch action；仅当宿主当前模式已提供工具编排时，顺序await参数已知、无需中途判断的调用，在面板刷新后集中读取。否则按单action执行；不另开进程、注入页面脚本或切换模式来绕过限制。同版本、同义项、同来源的术语证据可复用，但须关联全部应查ID；TM与TB分别记录，不能用TB或本批自匹配冒充独立TM证据。不重复Observe已明确的结果，仅在内容变化、歧义或调用失败时补读必要面板。

## 方法参考：只读取当前需要的部分

- 中译英存在省略关系、长串动作、机制句或翻译腔时，读 [中译英方法](references/zh-en.md)。
- 英译中存在长修饰语、被动结构、语体或欧化表达时，读 [英译中方法](references/en-zh.md)。
- 新语域、人物声音、双关、宣传、FPS/体育或运行拼接问题，读 [游戏文本与表达](references/game-texts.md)。
- 对审校尺度、规范覆盖、TM适用性、技术警报或判定误报有分歧时，读 [依据与质量判断](references/quality-evidence.md)。

熟悉的方法不必每组重读；参考未启用/不可得时，依据岗位责任和已有有效信息继续，不冒称读过文件。不将参考一次性全部装入上下文。

## 与其他能力的关系

不替代原生工具、权限、计划或协作。按岗位职责使用原生委派；交接传真实范围、关键依据、责任与产物位置，不传全部父历史。独立审校使用单独的 Reviewer；父任务核对实际覆盖、查证和例外，不重复阅读整个双语稿来数段或证明进度。

Phrase回填用对应平台Skill，消费已收敛差异，不边输入边重新逐词审校。明确只做报告时不写Target或确认阶段。纯文件任务无需强制进入CAT，已有CAT专业任务仍承担其真实版本与覆盖责任。

CAT Reviewer／Proofreader 的正常 `cat_get_segments` 内容读取直接带完整双语、TM／TB、项目规则及关联对照；独立委派时首组已随交接送入，不再重复取稿。后续按 `continuationPaths` 连续阅读；CAT 编辑器也自动显示所选行的关联句段。浏览器审校把正常读取获得的双语导出或含平台稳定 ID 的完整快照交给同一工具，声明任务地址、范围总数和读取时间；不导入 CAT、不切工作方式。平台尚未取齐时只报告已取得范围；平台 TM／TB、Comments 和必要图片仍按线上流程核对。准备文件不代表已读或审校完成，不额外逐条／逐组查询或回执。

文件任务用 `linguist_working_copy`：`prepare` 取得完整双语工作稿并在后台准备 TM/TB；随后对实际审读稿调用一次 `references`，默认覆盖全稿，只有局部任务才传 `segmentIds`。常规首组正文随返回结果送入，其余按 `continuationPaths` 连续阅读，过长首组也在文件中完整保留；内联正文不重复取读。每组含当前译文、原始字段和备注、命中术语正文、TM 原译与自动替换候选。共用依据在组内去重，适用规则与关联源译文直接附入普通阅读组，横向索引用于整批关系、要求和 TM 差异复核；本地语义检索自动提供相关原文与最新译文的成组材料，首组直接送入、后续随正常阅读取得，无需另查语义分组；只是审校线索，不生成 QA 错误或自动统一译文。向量按原文和模型缓存，译文修改不触发重算；pending／failed 不表示没有关联。不每50条再请求一次资料。完整 JSON 保留出处和技术字段，必要图片及未附原件按引用查看。工作材料的存在不代表已审读，待检索与检索无命中分开；候选选择仍有范围，疑点需用现有检索补查。后续取资料不会覆盖旧组文件，同任务自匹配不能当独立历史依据。

`assemble` 保存私有草稿；完整审阅且无阻断后，`deliver` 按已读版本写回并验证原格式交付文件。实际沿用 TM 原译或适配候选时，可在对应 edit 中提供 `tmUnitId`；只有最终译文保留该采用且写入成功才计复用。接续 T→E→P 时，`sourcePath` 始终指原件，`previousResultPath` 指实际审读的工作稿，`previousResultSha256` 使用该稿返回的 `artifactSha256`；Reviewer 独立审读 Translator 最后保存的完整稿。保留原件 `sourceSha256` 与稳定 ID，版本由软件关联。`unchanged` 保留当前工作译文，未列 ID 仍未裁定。各会话交接使用工具返回的实际路径；`changes` 是本阶段差异，`finalChanges` 是对原件的累计差异，专业审校和平台提交以实际执行结果为准。

格式不兼容时，先检查具体文件与报错，选择现有工具或库；允许编写任务脚本或修复适配器，在原稿副本上核对内容对应、标签、锁定、未修改部分和输出可打开性，通过后继续已授权任务。可复用修复进入对应适配器，验证缺口明确说明。独立 Reviewer 的语言审校仍须完整完成。

有实质收益才修订；自然表达不是擅自增事实，准确也不是照搬源语语序。不存在唯一标准译文，不要求每句给多个方案或长理由。只有需要客户/权限决定的缺口才交给用户，其余按专业判断完成。
