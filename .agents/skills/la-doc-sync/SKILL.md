# 同步 LA 使用说明

让译者能从实际入口完成受影响的操作，知道结果在哪里、有什么限制。以本次改动或用户指出的过时说明为起点。若只是内部重构，而且读者的操作和结果都相同，可以直接得出“无需改文档”。

**找到事实来源。** 沿改动找到实际调用者、界面、配置或产物。交付新版时核对根目录与插件清单、安装说明和压缩包内的版本。写兼容性时查宿主范围与已测试的构建，写格式或体积限制时查接收入口和共享常量，写文件去向和恢复时查实际写入与读取路径。说明结论的适用范围，例如已生成交付表、本地已导出和平台已提交是不同的结果。

**只更新读者会用的入口。** 译者的用途与安装入口在 README，具体操作在 QUICK_START，维护命令在 CONTRIBUTING。优先改已有权威段落，其余位置按需链接。产品内岗位规则和仓库说明各有读者。清理文件前查清代码、打包和文档中的引用。

**用改过的说明验收。** 从读者入口走一遍受影响的操作或用对应的合成检查核对结果。比如说明写“从批次找到交付表”，就从批次记录打开对应的 Excel，核对批次和版本。只改文字时校验变动的名称、路径和链接即可。最终说明验证到哪一步，把源码或打包检查与日常 Desktop 的实测区分清楚。仓库的测试、数据和发布权限遵循 AGENTS.md。
