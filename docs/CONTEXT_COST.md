# CAT 上下文与开销

本页说明模型可见内容、工具正文预算与恢复边界。预算以工具 schema 和实现为准，不能用字符数直接代替供应商 token 计费。

## 模型收到的内容

显式 CAT 选区携带发送时冻结的项目、批次和句段身份，不会因选中句段自动附带全部 Source／Target；空选区也不表示全项目。岗位和项目摘要由 system prompt 提供，正文、术语及参考资料按需读取。

`cat_get_translation_context` 返回实际 Source／当前 Target、适用参考及读取快照。模型可以按文稿或语义组工作，读取分页不决定翻译、写入或审校的分组。普通保留项不需要逐条生成决定记录。

## 正文预算

- `cat_get_segments` 默认读取 20 段，最多 100 段；按完整 JSON 的 24 KiB 预算缩小页面，沿实际 `nextOffset` 接续。
- 单条超出该预算时完整返回并标记 `oversized`；若宿主转存或截断，使用 `cat_get_translation_context` 的 cursor 分片完整读取，不能将路径或片段计为已读。
- `cat_get_translation_context` 每次最多 50 段；它与 `cat_read_context_doc` 的默认及最大文本响应预算均为 32,000 UTF-8 字节。必要正文通过 cursor／offset 无损接续，可选案例和参考计入预算。
- Linguist 预设保留原生 compaction，不另做工具结果首尾裁剪。图片仍须以实际视觉内容呈现，文本预算不等于图像推理预算。

## 接续与审校

读取快照、分片进度及待确认阅读记录随原生会话保存。同一会话热更新或重启后接续，原读取 revision 和 Source hash 保持不变；其他会话及分叉继承事件不能借用。

阅读记录仍要求完整正文进入实际模型请求，并得到成功响应。保存修改和明确范围的审阅登记可以合并调用；提案、写入成功和独立审校完成分别判断。独立 Reviewer、完整审阅范围及必要资料查证继续保留。

## 性能评估

性能评估应固定模型、effort、任务范围和资料，分别计量检索、工具执行、模型等待、往返次数和总耗时，同时核对遗漏、误改及最终语言质量。模型请求需区分未缓存输入、缓存读取和输出；不能把整次请求用量当作 CAT 选区增量。

TM 候选与源文特征在当前项目连接内复用；词库或来源设置变化时刷新，外部连接提交也会使缓存失效。普通译文保存不重建 TM 缓存。既有分数、候选排序及来源信息保持不变；只在数学上确定达不到原有门槛时跳过编辑距离计算，不使用近似候选截断。首次检索需要准备特征并占用相应内存；显式零分门槛仍完整评分，返回条数限制本身不减少评分工作。检索加速不代表模型等待或完整译审按相同比例加速。
