# CAT 上下文开销核对

2026-09-29 核对本机源 LA 及当前 DSH 目标代码。仅使用合成数据。用户决定本轮保留当前上下文内容，后续另行优化。

## 已确认的内容

旧 LA 普通项目消息会捕获项目、批次、显式引用句段、选区 ID、时间和 UI revision。它不会因为选中句段就把 Source/Target 全文自动装入消息。队列保留发送时快照，重试复用原消息快照；空选区不表示全项目。

当前 DSH 显式 CAT 引用使用同类身份快照。以下是实际 v2 稳定 ID、紧凑 JSON 和模型可见 XML 封套的合成尺寸，**不是 token 数**：

| 选中句段 | 完整封套字符／UTF-8 字节 |
|---:|---:|
| 0 | 318 |
| 1 | 391 |
| 10 | 1,057 |
| 100 | 7,717 |

上例包含项目和批次 ID，没有句段正文。选区最多100个 ID；字符数随实际字段而变。

岗位和项目 Digest 是独立的 system prompt 部分。旧 LA 空合成项目的四岗位部分为2,077–2,181个JS字符，完整LA部分上限18,000字符，超过时裁剪Digest。2026-09-29 的目标版未绑定项目时为1,926–2,046字符；这不是升级后的数据。

2026-10-02 的 **1.1.0** 未绑定项目、CAT 模式实际组装结果为：General 2,561 字符 / 6,383 UTF-8 字节；Translator 2,545 / 6,353；Reviewer 2,604 / 6,376；Proofreader 2,553 / 6,351。包含共享专业短核与岗位方法，不包含宿主提示、工具定义、Skills 目录或聊天历史；这些尺寸不是 token。整体上限仍为18,000字符。

正文另按需读取：`cat_get_segments`默认20、最多100段，没有完整结果字节上限；`cat_get_translation_context`每次最多50段，文本响应默认64KiB、最高256KiB，并在该页内去重相关参考。

1.1.0 的任务功能卡与最多两组相关教学案例计入同一字节预算。案例只按需选择，预算不足时先移除；不会因 CAT 选区而自动把整套案例塞进每条消息。当前标准在 system prompt 中重新组装，案例正文通过实际 CAT 工具结果进入当前对话。

## 尚不能归因的性能差异

没有同模型、同任务、同历史的LA与Codex对照，不能把速度差归因于CAT选区。原LA工具执行为sequential；模型路线、工具轮次、正文回读、历史长度和缓存也需要一起测量。

一次历史DSH合成请求的选区为空，仍记录200个未缓存输入token和19,328个缓存读取token。这是整次请求的19,528个输入token，不能当成CAT选区增量，也不能据此判断本轮rc.2性能。

后续优化应按真实请求分别计量常驻提示、工具定义、选区快照、工具正文、历史及缓存。保留专业判断必需的Source、当前Target、上下文与证据，避免把缩短输入变成遗漏审阅。
