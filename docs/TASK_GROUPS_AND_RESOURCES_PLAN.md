# 项目、任务组、工作批次与两层资料方案

本文记录 2026-11-18 的历史设计依据与阶段性验收目标，仅供追溯参考，不作为当前运行或交付门槛。日常操作见 [使用指南](../QUICK_START.md)。

## 1. 要解决的问题

项目持续接收多批任务，既有长期共用资料，也有仅适用于某个月、某个版本或某次来稿的资料。新增一个可自行命名的任务组，把任务和资料按真实来稿组织起来。

```text
示例项目                         项目共用资料
├─ 2026年11月                    本组资料
│  ├─ 第一批台词审校
│  ├─ 第二批活动翻译
│  └─ 第三批商店文案
└─ 新版本发布                    本组资料
   ├─ 首批
   └─ 补充批
```

对用户而言：选定一个工作批次后，LA 自动知道它属于哪个任务组，使用项目共用资料和本组资料。GUI、General、CAT、工作副本、线上审校采用同一归属和同一份资料。

## 2. 制订方案时的实现

- 当前 CAT 的工作批次对应一个导入文件 `Asset`；`cat_list_batches` 返回的 `batchId` 就是 `asset.id`。不是已经存在一个可直接插入父级的通用文件夹模型。
- `Asset` 目前按项目、文件名和源文件内容生成身份。同一文件在同一项目内重导入会复用身份；新方案必须处理跨组独立任务的情况。
- 会话绑定已有工作区、项目、岗位、工作方式、委派范围，没有任务组。
- 项目资料登记在项目资料库中，同时纳入 CAT 已导入的 TM、TB 和背景文档。`appliesTo` 是角色、模块、文本类型等适用说明，没有任务组归属。
- 普通问答、工作副本和审校已有共用资料准备能力；TM／TB 主要按项目检索。现有语义缓存能复用源文向量，读取时装配当前译文。
- 新资料 GUI 与 `linguist_prepare_project` 已共用维护后台，可以在这套实现上扩展。

## 3. 层级与归属

| 层级 | 职责 | 必要信息 |
|---|---|---|
| 项目 | 一个长期维护的本地化项目，持有共用资料和现有项目设置 | 沿用现有项目 ID、语言对、工作区及设置 |
| 任务组 | 一次来稿、月份或版本的集合 | 稳定 ID、所属项目、自定义名称、创建时间、归档状态 |
| 工作批次 | 实际处理的一份稿件或一个平台文件任务 | 稳定身份、所属任务组、原有来源及处理记录 |

- 任务组名字由用户决定，例如“2026年11月”“冬季活动”“客户第二轮返修”。月份只是命名方式，不按系统日期自动改组。
- 每个任务组只属于一个项目；每个工作批次只属于一个任务组。
- 每个项目有一个正常的“未分组”任务组。简单任务和归属尚未明确的历史批次可以直接使用它，不增加开始工作的必填手续。
- 任务组沿用项目语言对和现有默认设置；这轮不增加另一整套岗位、模型和权限配置。
- 重命名任务组只改名称，不改 ID、文件路径或缓存内容。
- 同项目内可批量移动工作批次，保留批次／句段 ID、修订、锁定、审校记录和导出物。移动后按新组重新取得适用资料，已有材料包标记为需刷新。
- “移动批次”与“将同一文件作为新任务导入另一组”明确区分。后者建立独立工作批次和修改记录，可以复用原文件内容存储，不能让两个组共享同一份可变译文。组内重导入沿用原有去重行为。

DSH 工作区继续绑定项目。任务组在 LA 内管理，不要求为每个月新增 DSH 工作区、移动磁盘目录或改变模型配置。

## 4. 资料的两层结构

### 4.1 资料范围

| 范围 | 示例 | 默认取用方式 |
|---|---|---|
| 项目共用 | 通用 SG、长期 TB、项目 TM、世界观、角色设定 | 所有任务组继承 |
| 任务组专用 | 本次术语补充、版本 TM、截图、客户 Query、临时规则 | 仅所属任务组使用 |

当前任务的有效资料 = 项目共用资料 + 本组资料，并去除明确在本组被替代的资料。

“属于哪个层级”与“适用什么文本”分开：前者决定是否进入检索范围；现有 `appliesTo` 继续表达 UI、角色、模块等专业适用性。客户文件不需要增加固定字段，范围由 GUI 或 General 登记。

同一文件在多处引用时复用已有内容、解析结果和向量；归属记录与文件内容分开。移除一个组的引用，不得停用其他组仍在使用的 TM／TB 或删除原件。

会话中临时提供的附件仍可作为本次任务输入；只有登记为长期资料时才选择项目或任务组归属，不强迫所有附件先入库，也不增加第三层长期资料库。

### 4.2 冲突与版本

- 放在任务组层不等于自动比项目层更权威；文件日期较新也不等于获批。
- 补充资料默认与项目资料一起使用。客户明确给出本组替代要求时，可以将“本组新版”关联为“仅本组替代指定的继承资料”，界面显示替代关系。
- 替代必须指向明确资料；整份替代与局部术语例外不能混淆。局部例外仍把相关项目规则与客户例外一起提供，让审校根据明确依据判断。
- 未说明如何处理的术语或规则冲突，保留双方完整依据并提示。TM 匹配率、来源范围和客户确认状态分别表达，不把“本组资料”当作匹配加分或质量批准。
- 普通替换、替代继承资料，都在新文件读取成功后生效；失败时保留原有可用资料并显示错误。
- 本组资料升级为项目共用属于明确的范围变更，GUI 和 General 都能做；不会因为某条译文被采用就自动推广到全项目。

### 4.3 历史与跨组参考

- 当前组以当前有效资料工作；旧审校记录保留当时使用的资料身份、内容版本及已有材料出处。
- 新资料不会自动改写已交付译文，也不会把旧审校记录改成“已按新版要求检查”。继续旧任务时说明依据发生了什么变化，重查受影响内容。
- 默认关联检索可覆盖同组其他批次，写入和审校覆盖仍限于本次指定批次／句段；相关材料不等于扩大修改范围。
- 用户要求跨组比较时，可一次选多个组，按组标明来源和规则。其他组的规则不会因此变成当前组的执行要求。
- 项目共用 TM 中本来就存在的历史译文仍可正常检索；单独留在另一个任务组中的专用资料不会自动混入。

## 5. GUI

### 项目主页与批次入口

项目卡片进入任务组列表，显示各组名称、批次数和现有可计算的状态；支持新建、改名、归档和恢复。展开任务组可查看工作批次，并批量调整归属。

项目级“项目资料”入口继续保留。任务组有“本组资料”和“新建 LA 会话”入口。会话、CAT 和批次详情显示“项目 / 任务组 / 工作批次”，方便确认当前范围。

导入入口自动采用当前任务组；未选组时进入“未分组”，可以在同一个导入表单改选或新建组，不增加单独问答。导入任务进组后，General 和子代理自动沿用。

### 资料页

复用现有管理页，增加任务组选择和来源标记：

- 项目视角：维护共用资料，可切换查看各组资料。
- 任务组视角：显示“从项目继承”和“本组添加”，以及本组明确的替代关系。
- 保留查看、添加、替换、移除、用途、适用范围、读取状态和错误说明。
- 本组页面新增资料默认归本组；项目页面新增默认归项目。保存前可见且可修改归属。
- 编辑继承资料时明确进入项目级编辑；“仅本组替代”是单独动作，避免一个月的更新影响所有月份。
- 支持批量调整资料归属，尤其用于首次整理历史资料。
- 保留 1 GiB 接收上限、原件保护及已有暂存释放机制。

使用 DSH 原生组件、主题和顶部间距；宽窗与窄窗共用布局规则，不修改宿主界面源码。

## 6. General 接口、会话和子代理

扩展现有项目准备、资料维护和绑定接口，统一支持任务组，不再另造一套 Agent 专用资料库。

General 能在一次维护调用中完成必要操作：查看／创建任务组、确定当前组、登记批次、调整批次归属，以及添加／替换／移除资料和调整资料范围。GUI 调用同一服务。

示例指令：

> 给这个项目建“2026年11月”组，把这三份稿件放进去；SG 放项目共用，新术语表和截图只用于这个组。

范围确定规则：

1. 已选工作批次时，从批次归属确定任务组。
2. 任务组入口创建的会话，直接携带任务组。
3. 项目级普通咨询只自动使用共用资料；明确涉及某组时切入该范围。需要跨组比较时明确带多个范围。
4. 正式任务没有分组线索时使用“未分组”；只有真实歧义影响资料选择时，才一次性澄清。不会逐句询问归属。

任务组绑定以会话／任务为单位，不使用一个全局“最后选择组”影响其他正在运行的会话。并发处理两个组时，各自保持范围。

专业委派及 DSH 普通子任务路径都传递实际岗位、项目、任务组与既定处理范围。Reviewer 独立从同一原始资料范围取得材料，不只接收译者挑出的引用或结论。

只有项目绑定的旧会话仍可做项目级咨询；打开已有批次或继续明确的文件任务时自动取得其组归属。重启和热更新后保留有效绑定。

## 7. 共用资料索引与三种工作方式

### 共用后台

增加任务组归属及资料引用范围；复用现有解析器、原件来源、TM／TB 数据和资料页面后台。

任务组、批次归属与资料范围的事实来源放在项目侧的共用存储。会话绑定只保存选定范围，GUI 只展示后台结果；缓存不能成为另一份归属事实。资料原文和解析结果继续使用现有存储，不为每组复制整套项目数据库。

服务端根据当前项目、任务组及任务来源，先计算有效资料集合，再进行 TM／TB 匹配、关键词和语义检索。所有入口采用这一步，不让模型自行过滤其他组。

范围过滤必须发生在候选数量限制和排序之前，避免先被其他组占满结果，再过滤成“没有匹配”。现有 TM 匹配算法、自动替换候选和 TB 核对能力保留。

CAT 导入的资料、GUI 上传的资料、General 登记的原文件都进入同一范围判断。项目规则、句式、示例及人工维护术语等非文件条目也要有明确归属；不能只给文件列表加组字段，其他数据仍按全项目取用。

资料身份与引用位置分离：同一路径或同一内容可以在不同组引用，不能因当前“按路径查登记”的方式而互相覆盖。删除、停用、替换应操作选定范围，只有没有有效引用的来源才从当前检索中退出。

相同材料去重后仍保留全部适用出处与确认状态，不能只因文本相同就合并丢掉来源或客户确认信息。

### 三种方式及普通问答

| 入口 | 如何取得任务组 | 如何准备和使用资料 |
|---|---|---|
| CAT | 当前工作批次归属 | TM／TB 面板、自动替换、QA、Reviewer 材料全部用有效集合 |
| 工作副本 | 当前批次／会话；写入现有工作副本元信息 | 后台按组预取；阅读材料直接带相关源译文、TM／TB 和规则 |
| 线上审校 | 会话选择的组与平台文件／任务关联 | 原导出或快照直接使用同一后台；平台 TM／TB、Comments 和锁定状态照常核对 |
| 普通问答 | 当前会话范围或明确指定范围 | 自动提供相关依据；无需先导入 CAT |

纯文件和线上任务需要在组内可见时，只做轻量批次登记，记录来源及现有材料／交付引用；不伪造 CAT 导入，不复制一套句段数据库。已导入 CAT 的同一任务关联现有 `Asset`，不重复显示两个工作批次。平台任务使用实际稳定文件标识，不能只凭同名标题合并。

读取材料继续采用已有的渐进式披露：公共要求提供一次，专项规则随相关内容提供；完整记录、出处和必要图片可取得；无明确文本类型时不靠相似度排名丢掉规则。同一材料包内重复引用去重，新的独立 Reviewer 仍得到完整所需依据。

不新增逐条／逐组查询回执，不恢复“每 50 条手动查库”。已有材料完整性信息不替代实际审校。QA、重复译文传播和写回范围也须跟当前任务走，不能因为共享项目而修改另一个组。

确认译文回写到 LA 自建 TM 时保留原工作批次／任务组归属；只有明确选择项目共用才扩大使用范围。原有项目共用 TM 继续作为共用来源。

## 8. 缓存与更新维护

区分“文件内容是否变了”和“谁能使用这份内容”：

- 内容解析、TM／TB 索引和语义向量按内容版本及相应解析／模型配置复用。
- 匹配、分组及最终材料缓存包含有效范围、资料版本和实际源文范围；范围变化不能复用别组的结果。
- 语义向量复用不携带旧译文，供稿时始终装配当前 Target 和有效出处。

| 操作 | 需要刷新 | 可以继续复用 |
|---|---|---|
| 修改任务组名字 | 名称和导航 | 解析、匹配、向量和材料内容 |
| 本组增加／替换／移除资料 | 本组受影响的匹配、规则材料和 QA 依据 | 其他组结果、未变文件的解析和向量 |
| 项目共用资料变化 | 实际继承该资料的组 | 未变的内容缓存；已明确替代该资料的组结果 |
| 移动工作批次 | 新归属下的资料装配、受影响检查 | 原文件、源文向量、译文及历史记录 |
| 只改译文 | 当前译文、相关 QA／审校材料 | 源文向量 |
| 只调资料归属 | 有效集合和检索结果 | 同内容的解析、匹配索引及向量 |

General 与 GUI 共用更新机制：登记工作区原文件后，在正常取用时检查变化；上传副本通过替换更新。此次层级调整不增加全盘扫描、自动猜最新版或持续后台重算。

缓存清理可选当前组或整个项目；组级清理只移除该组的派生结果，不能顺带删除其他组使用的共享内容。既有审校记录保留，依据变更与需要复查的范围可见，不自动重跑整项目。

## 9. 现有项目、资料和会话怎么处理

| 现有对象 | 处理办法 |
|---|---|
| 项目、工作区绑定和设置 | 原 ID、路径及配置保留；新增任务组目录信息 |
| 现有工作批次 | 首次升级时登记到本项目的“未分组”；原批次／句段 ID、锁定、译文、修订、审校和导出记录保留 |
| 现有资料登记、CAT TM／TB、规则等 | 默认保留项目共用身份，维持升级前的可用范围；内容不变时不重新解析或计算向量 |
| 已有工作副本与平台任务关联 | 保留现有来源和结果；能对应既有批次的直接关联；尚未登记的在继续任务时登记，不扫描全部历史聊天来猜归属 |
| 已有会话与子任务 | 不新建替代会话；已有批次范围可推导组，只有项目范围则继续项目级；旧结果的执行者及版本记录保留 |
| 未变化的原文件、管理副本及交付物 | 不移动、不重写，仅补归属信息 |

**历史资料的真实范围不能凭文件名准确还原。** 默认保留共用身份可避免升级后原本能用的资料突然消失，但过去混在项目里的某批专用资料仍需整理。资料页集中列出，General 可根据用户明确说明批量放进对应组；不自动按文件时间或“11月”等字样归类，也不要求先整理完才允许工作。

首次数据结构升级复用现有备份和事务机制：保存升级前副本，一次补齐任务组与引用归属，失败不留下半套结构；成功后所有新旧数据都走同一模型和读取路径。不会保留两套长期兼容实现。旧数据保护属于此次升级必要范围，不扩展成另一个迁移产品。

资料缓存只升级必要的范围信息。旧缓存若不足以证明适用范围，舍弃受影响的派生结果，重用已验证一致的内容缓存；不能为了“复用”继续返回混组材料。

## 10. 归档、移动和删除

- 归档任务组：隐藏在默认列表之外，可恢复；保留批次、资料关系和历史记录，按现有归档语义只读。
- 归档组的专用资料不进入其他组的正常检索，项目共用资料不随之停用。
- 删除空组可以直接处理；有工作批次或本组资料时，先在同一次操作中明确移入哪个组，或使用归档。不会隐式连带删除项目数据。
- 移动批次时显示它将使用目标组资料。资料更新、移组和归档只触发必要的范围重算，不新增逐句确认。
- 备份／恢复、项目复制及导入导出项目包须包括组和资料引用。恢复后不能只剩界面分组，后台引用却丢失。

## 11. 同轮实施顺序

1. **先接通最小完整路径。** 增加任务组与归属模型，在两个合成组中走通“登记批次 → 计算有效资料 → 真实 TM／TB 检索 → 返回材料”，包含历史数据补齐。
2. **接入所有业务入口。** CAT、工作副本、线上材料、普通问答、General 维护、专业委派及普通子任务共用范围解析；同步缓存、QA、TM 回写和交付相关调用。
3. **补齐 GUI。** 项目主页、任务组列表、批次归属、资料两层视图、会话当前范围及已有设置入口。
4. **统一收尾。** 验证真实安装包、DSH 桌面操作、文档与工具说明；整轮完成后交付，不发布只有前端分组的中间版本。

复用现有数据库、资料服务、解析器、匹配器和原生控件。实现时以一个共用范围解析入口贯通各调用方，避免给三个工作方式各写一套筛选逻辑。仅修改 LA，保持 DSH 和官方 `ego-browser` 技能的产品边界。

## 12. 验收条件

使用纯合成项目，覆盖一个项目、两个自定义组和“未分组”，不提交客户样本。

1. 项目共用资料在两组都可用；两组各自专用资料不串用，含 TM、TB、规则、图片和 Query。
2. 同一句源文在两个组中有不同专用术语，所有入口都取得正确材料；先过滤再限量，不出现被别组挤掉的匹配。
3. 同一文件在两组作为独立任务导入后，修改互不影响；移动原批次仍保留身份和历史。
4. Reviewer 不主动查组也能收到相关源译文、适用 TM／TB 和必要上下文；仍独立完成全范围语言判断，不能用“材料已送达”冒充已审校。
5. GUI 和 General 双向维护后立即看到同一结果；一个组替换或移除共用内容的引用不会破坏另一组。
6. 本组更新只刷新本组依赖；公共资料更新刷新实际继承者；改组名不重算；重复取用向量不重复计算，材料中的译文仍为当前值。
7. 旧项目升级后批次、资料、锁定、修订、会话和交付记录完整；再次打开不重复建组或重复导入。
8. 并发会话和独立子代理保持各自任务组；关联阅读不扩大编辑范围，重复传播／确认／导出不误触另一组。
9. DSH 桌面端验证组管理、资料管理、会话入口、窄窗布局，以及 CAT、工作副本、线上快照三种材料路径；线上合成测试通过官方 `ego-browser` 链路，不接触真实客户任务。
10. 固定同模型、同样本、同资料，对比工具调用、材料返回量、解析／向量计算次数和实际完成时间；同时核对术语、规则、标签、独立审校结果及已知应发现的问题。不能只凭 QA 数量不变宣称语言质量不变。

验收以范围正确、资料完整、操作省事和最终语言质量为准，不增加另一套给 Agent 填写的回执或报告流程。
