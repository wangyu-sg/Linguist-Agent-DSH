0. 新会话先知道的全部背景

0.1 产品与名词

Linguist Agent，简称 LA，是王钰用于实际中英游戏本地化工作的成熟桌面软件。现有架构已经有可复用的 CAT（计算机辅助翻译）领域内核、格式适配、项目数据库、专业工具、编辑器、参考资料与质量控制。本任务不是重新发明这些功能，而是迁走宿主依赖，完整保留专业能力和优秀交互。

Proma 是现有 LA 所依附的通用桌面 Agent 应用，底层使用 Pi。旧 LA 复用了它的 Electron 窗口、会话、模型、工具、浏览器和协作。迁移后不能为了继续调用旧 LA 而在后台运行 Proma 或 Pi Agent。

DeepSeek Harness，简称 DSH，是本次唯一目标宿主。它有原生 Agent、Session、Workspace、工具、模型配置、权限、子任务、附件、Web/桌面界面和插件机制。DSH 是宿主，不等于必须使用 DeepSeek 模型。用户原来选择的模型和思考强度应通过 DSH 的真实能力配置保留，不可擅自改为便宜模型。

BrowserSkill 是 Tencent/BrowserSkill 项目的浏览器能力，由浏览器扩展、bsk CLI/daemon 和 DSH 插件共同组成。此次选它作为唯一正式浏览器控制链；不是复制 Proma BrowserController，也不是让多个浏览器后端轮流尝试。

CAT 资产/批次/句段是领域对象；Session/Workspace是宿主对象。不可用“当前页面选中了哪个项目”代替工具执行的项目绑定。Stage是专业任务轮次及完成证据，不等于聊天回合，也不等于 Phrase 网站的任务状态。TM/TB分别是翻译记忆库、术语库；Context、Style Guide、Voice 则是必要参考、风格规范和角色口吻资料。

OSgame 是过去暴露重复下载、假预检、标签、交接与等待问题的真实案例，实际项目在 Phrase 上完成。它只提供问题类型，不是本次要在本机修复的项目。新会话不需要原始证据 ZIP 才能施工；本规范已经转化为非客户合成回归。不得恢复现有 OSgame 资产、同步历史译文、迁移历史 QA/Stage、操作真实 Phrase 任务。

1. 不再讨论的产品决定与范围

1.1 唯一目标架构

一个可安装的 DSH 原生 LA bundle，带 Host 与 Client；现有 LA 领域包迁入新仓库作为唯一业务实现。BrowserSkill 作为独立受管依赖，与 LA 在同一 DSH profile 协作。原生对话、输入框、模型、权限、Workspace、队列、子任务继续属于 DSH。

不做 Codex 插件、不接 Codex app-server/ACP、不接 Ruflo、不维护第二套 Agent loop、不用 MCP 包装隐藏的 Proma。没有“先交一个只读 MCP，完整版以后再做”的里程碑。

1.2 三条并列、完整的业务路径

  1. 本地 CAT：项目/批次、全量专业处理、完整编辑器、术语与上下文、QA、Proposal、Stage、交付及维护。
  2. 文件工作副本：无需 CAT 入库，以原件和双语工作文件开展 T→E→P 接续、范围决定、差异产物及版本验证。
  3. Phrase 网页：直接在用户指定的浏览器任务中读取、审校、回填、核验保存和下载；不得强制 CAT 中转。

三条路径共享专业规则，但不共享虚假的状态：网页保存不等于 CAT Stage 完成；工作副本 JSON 不等于客户原生格式导出；Phrase confirmed 不等于 LA 审校完成或 TM 自动入库资格。

1.3 已批准与未批准的动作

本任务批准：在新仓库读写、引入迁移必需的固定依赖、下载并安装固定版本官方 DSH Desktop 成品、构建 LA 与 BrowserSkill 必需的薄插件适配、安装到新产品独立环境、创建上表桌面入口、启动/停止自己创建的服务、进行非客户合成与有限真实模型验证、在新仓库作本地提交、最终本机通知。必要安装和启动不再以“尚未获准发布”为由留给用户手工完成。

本任务未批准：修改源仓库、覆盖旧 LA/Proma/DSH 安装或默认 profile、删除用户数据、读取客户正文作测试、改真实 OSgame 或 Phrase、批量迁移既有 QA/Stage/译文、复制浏览器 Cookie、绕过登录/验证码/系统权限、破解旧 safeStorage、推送远端、发布 npm/GitHub Release、force-push、全局升级 Node/pnpm、关闭系统安全机制。

旧指令中“不替换安装版”仍适用于旧产品；这里新增的是并排安装新产品，不是替换旧产品。OSgame 的排除不影响通用备份/恢复与旧数据格式兼容功能本身的迁移和合成验证。

6. 领域服务迁移：机械分离优先，业务算法不重写

6.1 应保留的实现

保留 Core 的稳定 ID、Tag/Placeholder/ICU/锁与术语规则；Formats 的检测、解析、序列化和往返；Store 的 schema、repository、事务、CAS、历史、备份；Tools 的业务行为与完整结果；编辑器的选择、IME、草稿和撤销算法。

首轮抽离不要同时换 SQL 库、XML parser、全部 UI 状态库或格式存储结构。任何必须替换的运行时 API（例如 Electron utilityProcess）限于宿主适配，不借机另做领域重构。

公开参考的 project JSON schema 1 要求 promaWorkspaceId。不得把 DSH workspace id 写进这个旧字段。新项目元数据移除对 Proma 的硬依赖；旧字段作为保留的历史元数据读取。

新 DSH 关联属于插件状态：projectId ↔︎ dshWorkspaceId。若现有 JSON reader 不能表示无 Proma 的新项目，增加明确的新 metadata 版本和向后读取；默认不动 CAT SQL schema，不重算 ID，不批量改历史业务表。备份恢复只在用户选定副本时发生。

6.4 事务、worker 与文件

项目服务拥有 DB 句柄；UI/工具借用，不各自 close。纯解析/QA 可并发；同资产写入沿用事务/CAS，不能全局串行化全部项目，也不能为了并行把同一段交给两个写者。

worker 只接业务输入与取消信号；无裸 DB 句柄、整个 Host、凭据或用户目录。调用完成后再发布成功；已经提交但通知失败，返回/恢复真实已提交收据，不反报“未写入”诱发重试。

node:sqlite 能力以实际选定 Node probe 为准。不可用时，允许安装符合条件的项目私有 Node；不换假数据库、不让 UI 显示写入成功。

7. Session、角色、范围与双窗口的绑定

7.1 插件合同（新设计，不是 DSH 既有类型）

interface LinguistBinding {
  version: 1;
  sessionId: string;                  // DSH 真实 Session
  workspaceId: string;                // DSH 真实 Workspace
  projectId?: string;                 // CAT 路径需要；工作副本/网页可以没有
  role: 'general'|'translator'|'reviewer'|'proofreader';
  workMode: 'cat'|'working-copy'|'browser';
  taskScope?: { batchIds: string[]; segmentIds: string[]; scopeVersion: string };
  bindingRevision: number;

}

角色/项目绑定是持久配置，不根据模型文本猜；当前 viewport 的选择只影响视图。所有 Agent 工具通过真实调用者找到 binding，模型不传 projectId。UI 显式项目操作可传项目 ID，但须解析为当前允许打开的真实项目；它不是 Agent authority。

7.2 存储与生命周期

绑定和专业委派关联存插件自己的小型持久状态（复用适合的 DSH storage domain；若已发布外部注册不可用，就用一个原子 JSON 状态文件）。不要新增整套会话数据库；CAT 业务事实仍在现有 CAT Store。

先预留会话身份/原生创建上下文、写入待激活绑定，随后通过真实 agent/created 在第一模型请求前完成岗位与工具注册。失败撤回本次绑定，不留下能越权执行的半绑定。DSH 当前 continuable spec 提供 caller-reserved childId 可用于在子物化前关联；按实际安装类型验证后使用。[S10]

不依赖声明合并写入未知必需 Session 事件。LA 状态变化若需要模型看到，使用 DSH 已支持的消息/Prompt 接口；只展示的变更走插件 SSE。可选 ignorable 日志不能成为绑定、恢复或专业完成的唯一真源。[S08]

7.3 角色规则

空白会话可切换岗位；已持久化用户业务请求后的岗位固定，换岗位创建新会话/子会话。用户明确请求超出岗位默认职责的通用任务，仍可执行，不能把角色当权限名单。

  • General：导入、分析、脚本、术语、QA、交付和按需委派。
  • Translator：对声明范围生产级翻译与自检，不交低质量草稿。
  • Reviewer：全量 Source＋当前 Target＋必要上下文；只改实质问题，保留正确译文；不能默认只审 Proposal。
  • Proofreader：独立目标语成品校对，必要时回看 Source，记录自己本轮决定。

角色资源从本地 resources/linguist-roles 完整迁移，包含公共质量合同；不用新写的三段通用“你是翻译专家”覆盖成熟 Prompt。

7.4 暂停、恢复与分叉

同任务恢复保留已冻结范围与任务轮次；显式新审校或真实输入变化按现有规则新建轮次。fork 可以继承项目/岗位配置，但新 actor 不能继承父的专业已读/已决定身份。删除会话不删除 CAT 资产或审校历史；卸载插件不删除项目。

两个窗口/会话同时打开不同项目，工具、用户编辑、返回和导航都按各自 binding 和 pane generation 解析。迟到结果不能切换或覆盖当前用户正在看的项目。

8. 原生工具接入与结果合同

8.1 保留行为，替换外壳

将 createLinguistCatTools 的业务 handler 与 Pi 形态分离，注册到 ctx.tools。工具外壳负责参数验证、调用者/绑定解析、AbortSignal、错误、canonical value 和模型/UI 投影；handler 仍调用原领域服务。

TypeBox schema 到 DSH schema 需逐类验证：required/optional、enum/union、数组长度、数值/字节上限、additionalProperties、nullable。不得转换失败就改成任意 JSON、删除校验或 as any 强行通过。现有 32 项参考清单见附录 A；本地新增项目须追加。

8.2 三种输出不能混淆

  1. 业务 canonical value：程序可用的完整、版本化结果；不含错误伪装成功。
  2. 模型 content：任务实际需要的信息。导入/管理动作可以摘要，专业 Source/Target/必要证据不能静默截断。分页和片段有可继续读取的明确定位。
  3. UI presentation：导航锚点、显示标题、进度。不要把 UI 的全部 tabs/trace/表格数据又写进模型正文。

对工具注册采用静态清晰映射，不自建能力平台。未配置能力不广告为可调用；注册失败保留明确错误，不让 description 声称存在一个未注册工具。

8.3 写入与错误

CAS、locked、Tag/ICU 和硬术语规则继续在领域层校验；用户的 full 模式不是破坏这些数据规则的开关。正常已授权任务不重复弹确认。破坏性删除、覆盖外部文件和改变客户任务状态维持其现有明确授权边界。

执行者生成的操作 ID 由实际 toolCallId/Session/调用阶段绑定，不让模型随意指定另一个调用者。相同实际调用重投不能重复写；网络不确定时可查询该操作的已提交收据，不是每次保存后强制再向模型发一轮回读。

如果 DSH 在已提交后因取消改变工具可见结果，领域保存的收据仍必须可查；UI 显示“已提交，通知/响应中断”或“结果待确认”，不让调用方盲目重做。

8.4 超时与并发

沿用 DSH 原生 exec.signal 与 scheduler，实际边界必须配套：业务 timeout、插件进程、文件传输、浏览器 CLI、宿主 deadline。不能只把一个数值改大。只对具有明确长预算的操作放宽，不全球无限等待。

纯读取只有能证明线程/Store/引用安全时标记 concurrency-safe。写入不能因名称含 read 就并发；“读上下文会创建 Stage/准备证据”的路径要保留真实副作用定义。

9. Client↔︎Host 接口：采用已工作的树外方案

9.1 本轮唯一 LA 传输路线

使用 DSH webServer 扩展注册一个有版本的 /la/v1/ 路由族，提供类型化 JSON 操作、同源文件传输及 SSE。仍在同一个 DSH Host中执行现有领域服务；不另开 HTTP daemon、不引入通用 RPC 平台。

这取代旧方案“给官方 api-remotes 增加静态 import”的假设。原生 DSH 的 Session/Workspace/模型 UI 仍调用它已有的 Client 服务；只有 LA 自有业务走上述外部扩展。不得 patch DSH core 来注入一套新 Remote registry。[S05,S06]

9.2 最小接口集合（新设计）

  • 项目目录/创建/打开/设置/归档等用户操作。
  • 已绑定 Session 的项目/岗位/范围查询与空白会话绑定。
  • 批次/句段/参考/QA/Proposal/交付/维护的既有服务操作。
  • 导入上传、获准的本机文件/目录选择，以及下载实际导出。
  • 单个作用域的状态流：第一帧 snapshot，后续 change/invalidated；带版本/游标/关联身份。
  • 实际安装/能力健康摘要，供启动器与 UI 读取；不泄露环境、密码、客户正文。

不要暴露任意 SQL、任意 JS、任意 Host 方法或可由请求指定 projectRoot 的通用调用。相同 handler 可被 UI 与 Agent 复用，不复制业务校验。

9.3 同源信任与身份

本轮只支持本机 loopback。Host 必须匹配本机 authority；Origin 存在时必须同源；拒绝 cross-site；写操作必须严格 JSON/授权上传格式；服务端验证路径/作用域，不能只相信 React 传值。localhost 也不是“任何网页都可读本机数据”的许可。

复用 DSH 同源/调用者策略可用部分并参考 BrowserSkill 的已实现边界。不要绕过原生权限，也不建设企业 RBAC。文件 URL 使用受控不透明句柄，不暴露整个磁盘路径作为公共静态资源。

9.4 正确的重连和文件流

SSE 每次连接先给该作用域完整基线；先订阅再取得一致快照，或用版本水位保证无缝，不做“GET 后再 SSE”的竞态。断线保留最后可用视图，重连时原子替换，迟到 unary 响应不能覆盖更新版本。

大文件用受限上传/下载流，不在 JSON 内传数十 MB base64。浏览器端 File 不是本机原始路径：上传得到受管 staging handle 后 prepare；目录逐项保留相对层级，防止路径穿越。远程文件服务不属于本轮；不把 Web 用户浏览器路径当 Host 路径。

9.5 Client 模型和 UI store

Client model 是 Host 事实的 React-free 投影；存储 selection、draft、panel width 的是视图 store，不是另一份 DB。组件通过 DSH Slots 的 hooks/props 获得数据，不直接接 ctx 或手写全局事件总线。一次项目读取服务多个面板，不逐行发请求；无需为了 plugin 形式重写稳定的纯编辑算法。

10. 专业 Stage 与模型证据：不能在换宿主时变弱

10.1 保留业务含义，不死搬 Pi 字段

以下状态必须区分：资料存在、工具已返回、最终请求包含资料、请求实际进入对应 Provider、模型作出了决定、当前修订已提交。聊天结束、工具成功、UI 预览、PTC 变量里有正文都不能跨级算完成。

沿用本地源的 Stage 计划、baseline、scope、revision、required evidence、decisions、blocking gaps。新宿主只替换事实取得方式。不得因为证据接入复杂就把 onEvidencePrepared 或最终请求证明改为空函数。

10.2 接入方案

  1. CAT 内容工具在现有领域计划下产生待呈现记录：Session、Stage、资料身份/版本、文本范围或图像标识、toolCallId；正文只保存在已有受管内容或正式工具结果，不额外写日志副本。
  2. 在 DSH 官方模型请求/流扩展点观察经过上下文、裁剪、工具结果处理后的真实请求，核对待呈现内容是否实际包含。使用 DSH 现有不可变请求、message/tool identity 和附件投影，不只读 agent/pre-step 的早期候选。
  3. 原生 llm/stream 和确实返回的 Provider 流事实用于记录提交证据，绑定真实 route/model/request/attempt。它不是通用 HTTP2xx 回调；未观察到 HTTP2xx 时就不能把记录命名为 HTTP2xx。
  4. 保持工具返回、最终投影、成功响应证据的层级。可用非错误 Provider 响应证明该请求确实被处理时，以明确的新 evidence kind 记录；仅连接建立、start 占位或空失败流不算。
  5. 提交记账与结果通知分离。只有本地记账失败时，重试本地事务，不要求模型重读整份客户材料、重做语言任务。

把接缝实现集中在 dsh-linguist/src/host/evidence.ts 及既有领域 evidence 模块。准确事件签名从已安装 dsh-llm、dsh-agent-loop 源码/类型取得；使用独立 contract test 证明该扩展点在真实安装包而非仅源码测试中触发。若原生公开 hook 不足，做一个作用于 LA 调用的薄 LLM waterfall adapter，转交原 next() 且保留 signal/request；不捕获全局 fetch，不自己实现模型请求、不引入第二 loop。

10.3 专业决定与完成

Reviewer/Proofreader 的完成仍由冻结范围内的当前修订、本人本轮决定、必要资料与阻断条件计算。合法 unchanged 与 corrected 都计入覆盖；遗漏不是 unchanged。人工或并行写入造成 revision 变化时，只使受影响决定/证据失效，不一律重审整个项目。

cat_confirm_segments 只能记录该任务允许范围；已导入的 reviewed/外部 confirmed>=2 不自动产生本地专业决定或 TM 资格。不要通过修改状态字样让进度条变成 100%。

10.4 压缩与恢复

使用 DSH 原生 compaction；不复制全部历史、不另设不断摘要的后台 Agent。不为本轮迁移预设长会话必须分拆、降 effort 或提高压缩阈值。

区分“以前某请求确实得到资料”与“当前上下文仍有资料”。保留 durable presentation 事实；新决定需要的版本内容若已不在当前请求，就只补相应文本/图像或必要规则。通过请求投影检测，不让模型每步机械重新读一遍。

不会将 summary/hash/文件路径伪装成原文。跨页共享内容可响应内去重；不要仅因以前出现过就永久从后续必要上下文删除。模型缓存命中不是业务已读证明。

10.5 PTC 的定位

DSH 程序化工具调用可组织文件枚举、转换、批量 QA/诊断聚合和已明确的小组网页动作。专业审校的完整 Source/Target 和必要规则必须实际到达作出语言判断的模型，不能只在 run_code 内取得全文并输出摘要后宣称全量审校。

默认成熟路径使用 DSH 原生普通工具模式；PTC 是同一原生系统内的可选组织方式，不新增独立工作流引擎，不默认开启全局工具结果压缩。测试必须覆盖 PTC 隐藏正文不能获得专业完成资格。

11. 专业子任务：原生执行、输入一次送达

11.1 生命周期仅由 DSH 管理

复用 DSH ctx.subagents 的本地原生 provider、continuable 子会话、message、interrupt、原生任务状态。LA 的专业委派接口只提供岗位、项目、冻结范围与显式输入，不保留 Proma runner、delegations Map、跨进程等待协议。

General 可以自主按任务使用 Translator→Reviewer→Proofreader，也可以只委派一个阶段或不委派。不得把全流程固定执行三遍，也不得让父子双方重复审同一范围来充当默认质量机制。

11.2 任务合同（新设计）

interface LinguistDelegationSpec {
  role: 'translator'|'reviewer'|'proofreader';
  objective: string;
  scope: { batchIds?: string[]; segmentIds?: string[] };
  inputs?: Array<{ path: string; purpose: string; required: boolean }>;
  expectedOutcome: string;
}

项目从真实父 binding 来，不接受模型传任意项目根。角色在子首次请求前绑定；scope 从父项目当前真实 ID 冻结。空范围专业任务拒绝，General 文件/网页任务不能被“没有 CAT 句段”误拦。

11.3 文件交接

父相对路径由父实际 cwd 解析。路径通过当前 DSH 文件系统/授权策略；不同 execution world 的路径必须在其原生文件设施下物化，不能把 Host 本地绝对路径传给远程 sandbox 假称可读。

在子可访问的已授权共享目录可直接引用；需要固定输入时只复制明确指定文件到子只读 input 区，生成 path/version/hash/purpose 收据。必需文件缺失或权限不足时，在启动该专业子任务前返回 blocked-input；不得让子搜索旧资料十分钟代替当天材料。

宿主一次验证送达即可，不要求父/子各额外发一个模型工具回合证明文件存在。收据不等于子实际阅读。父对子返回的结论须保留 checkedInputs/notChecked 与专业结果，不能把“completed”包装成“全部验收”。

11.4 等待、取消和迟到结果

等待使用原生状态和有界等待，不搬旧 120 秒 RPC。长子任务持续存在与父正在等待的区间分开记录；父可以做独立工作。明确区分取消等待、停止子任务、取消整个任务树，沿用所选 DSH API 的实际语义，不擅自把其中一个变成另外两个。

子任务失去绑定、scope 变化或父任务已结束，迟到结果不能写入其它项目。可接续的任务在恢复后通过现有 revision/coverage 判断下一范围，不重新从头执行整个资产。

12. 导入、格式、原生结构与交付

12.1 格式支持不得裁剪

保留本地当前注册的所有 adapter。公开最低参考为：MqXliffAdapter、XliffAdapter、SdlXliffAdapter、PhraseMxliffAdapter、PhraseDocxAdapter、CsvAdapter、JsonAdapter、XlsxAdapter。保留探测优先级、语言/确认状态、原生 inline code、注释/批注、键、编码与锁。[S03]

TM/TB/Context 等资源导入路径也要迁移，不把“八种批次格式”当所有资源格式。

12.2 真实 prepare 是共同入口

UI 与 Agent 共用现有的 prepare/parse/commit。显式 kind=batch 只是用途声明，不等于格式有效。dryRun 必须做真实解析但不写 Store；commit 不换另一套简化规则。通常直接 import 内部完成 prepare，不能要求模型每次先 dryRun 再 import。

相同内容改变 .mxliff/.xlf/.xliff 后缀不得绕过 Phrase 的恢复/结构要求。supporting master、mapping、参考资源与待导入批次角色明确，不把 mapping.json 或整个 master 当作普通 batch ready。

12.3 Phrase split/master

保留当前按内容和身份解析的实现。区分数字占位符、{u>/<u} 等包装、原生标签以及真实游戏变量；Source 和 Target 两侧检查。零数字占位符不等于无需恢复，probe score=0 也不能同时代表无需恢复、缺 master、解析失败和匹配冲突。

strong identity 冲突不能被正文相似 fallback 掩盖；相同 Tag 序列不一定是相同 master。候选读取/解析失败返回具体原因，不吞异常后输出笼统“没找到”。重建表示不能修改客户文字内容或删标签换通过。

12.4 三个独立正确性条件

原件保留、CAT 可编辑表示正确、原生导出可逆必须独立验证。同 SHA 无操作往返只证明第一类，不证明 Tag 已恢复为可编辑结构。标签、换行、锁和稳定 ID 不因换宿主改变。

12.5 QA、导出、撤销

cat_project_summary(includeDelivery...) 等只读查询不能触发 persisted QA、Stage 或导出；既有 QA 不能因 UI 刷新反复计算。真正运行 QA 时保留范围、版本与处置。

verified 和 as-is 的真实差别保留，as-is 不是绕过格式生成的万能成功模式；覆盖文件、明确豁免维持现有授权。格式内存验证不额外制造真实导出历史；真正交付导出记录必须保留。

UI 的“撤销导入”、编辑器撤销、撤销 Proposal、备份恢复是不同功能。迁移既有真实能力和引用检查，不把一个按钮称为安全更新系统。已有导出/QA/Stage 等引用阻止撤销时说明具体引用；不得删除历史解锁。此次不建设 OSgame 原位恢复或历史译文同步。

13. 文件工作副本完整接续

完整迁移 working-copy.ts/working-copy-tool.ts 及相关实现，不只保留 prepare。工作流程为：原件读取→完整双语工作稿→模型按连贯小组阅读并形成决定→assemble→下一岗位基于上一有效完整结果接续。[S04]

原始 sourcePath 一直指向原件，不将生成结果冒充 source。保留 sourceSha256、previousResultSha256、baseRevision、groups/edits/unresolved。缺失 ID 不能默认已审；已有 Target 只在经过校验的接续中使用，Source/ID/锁/原生 metadata 保持原件权威。

输出目录按原件身份与 Session 隔离，原子写；路径和 symlink 规则维持。一次 prepare 可用于多组处理，不每小组重新解析全文。assemble 返回 coverage、真实差异、仍阻塞范围和下一步，不能宣称 private JSON 已提交 Phrase 或已是原生交付。

UI 可列出工作副本、差异和接续状态，使用现有 file viewer/工作台容器，不要求用户手工编辑 JSON 才能开展正常任务。Agent 仍可使用 DSH 原生文件工具维护决定文件。

14. BrowserSkill：唯一正式浏览器后端

14.1 组成与安装身份

主链为 DSH Agent → BrowserSkill DSH plugin → bsk CLI → daemon → 指定 Chrome/Edge 扩展 → Agent Window。模型推理由 DSH 完成，BrowserSkill 不是第二个语言 Agent。

固定 CLI、实际 daemon、extension、DSH plugin 四个身份并验证功能匹配。源码 README 的能力不自动等于商店已发布扩展具备；不要看到同一版本字符串就跳过功能 smoke。

复用已连接、兼容的 BrowserSkill，不无故重启用户 daemon、关闭其它窗口或改变默认 Chrome profile。无现成环境时可安装 CLI 和打包插件到新产品工具目录；用户浏览器扩展安装/连接按官方方式，不能静默改 Chrome policy、Cookie 或安全设置。[S11]

14.2 不再安装两个默认浏览器控制器

LA 正式 profile 不同时挂 Playwright MCP browser-use、Chrome DevTools MCP 和 BrowserSkill。自动化测试可使用 Playwright 驱动隔离测试浏览器，这是测试基础设施，不是产品对模型的第二个 Browser 后端。

BrowserSkill 的原生右区承担实际浏览器预览，LA CAT 在另一个原生 Tab；不自建截图流、PiP 外壳或把它复制进 CAT。用户关闭预览后，不因每次新截图抢焦点。

14.3 文件传输 action 的必交付薄补丁

当前公开 BrowserSkill 六组 DSH action 没有直接覆盖 CLI 已有的全部文件传输能力。执行者必须从固定源码和实际安装包核实缺口，并在同一个 BrowserSkill 插件实例补 download、upload 的原生 action/工具，复用现有 runner、registry、queue、signal、结果投影和 UI 生命周期。[S06,S07]

推荐以 browser_files（新设计工具）承载 download/upload，或按上游当前规范加 action；名称可按真实公开实现调整，但不得另建第二会话 registry。兼容代码保存在 integrations/browser-skill/patches，应用到固定上游代码生成本地 tgz；保留原包来源、MIT、差异和构建 hash，只安装一份，不同时安装原版与补丁版。无需本次发布上游 PR。

  • 下载在点击前登记捕获，绑定实际 session/tab/target；调用现有 bsk download 的原子输出能力。不是点击后列 Downloads 最新文件。
  • 目标路径必须在当前允许的 staging/工作目录，不默认 overwrite；同名目标应明确冲突或分配不覆盖路径。
  • 延迟、取消、输出丢失返回 pending/unknown/failed 的具体事实；可确认旧调用时继续获取结果，不再次触发下载。
  • BrowserSkill 的浏览器级下载互斥不能被每 Session 队列绕过；出现忙碌时排队在正确所有者或明确返回，不启动多个竞争捕获。
  • 上传使用已批准的本地文件，并验证真实 file input/目标；选中文件不等于表单已提交，更不等于服务器保存成功。
  • 本轮采用本机模式；远程 BrowserSkill 不支持的文件传输不得伪装成功或偷切另一浏览器后端。

14.4 队列与预算

复用原插件每 Session FIFO 和可恢复 starts/stops。每动作启动 bsk 子进程不等于每动作必须向模型回一轮；可用 DSH 原生 PTC 将已明确的固定动作组织成有界程序，但不能用自造后台 JS 无限重试。

实际预算要覆盖 browser operation、IPC 余量、分块文件传输和输出收集。源 CLI 的内部期限+5秒不足以代表整段传输完成期限；外层 wrapper 不得在内层仍合法工作的瞬间先超时。

取消后不重放已成功前缀；清理只针对插件创建的 Session/本次 operation，不能 kill 所有 bsk、Chrome 或 DSH 进程。stop 的清理可能继续，状态和重试须指回原 session/requestId。

14.5 观察、动作与业务保存

保留 lazyTools 与按需 Skill reference；一次正确装载后复用，不每轮重复读完整 Skill。普通操作回显真实 session/tab/目标和具体状态，不重复带全部历史 trace。树/HTML 返回遵守有界范围/游标；必要正文不能静默截断。

预览截图轮询属于 UI 负载，不自动计为模型视觉请求；隐藏视图应停止图像采集，状态订阅可保留。真正截图工具结果进入模型时按实际附件计量。

动作的 dispatched、页面变化、保存成功分别表达。对已知小组，前置身份、操作和结果条件尽可能由同次原生执行完成；不要求每次 click/press 后再向模型返回完整 Observe。

14.6 Phrase 专业约束

任务开始明确项目/作业、语言、批次、编辑阶段、范围和用户目的；这些不是仅凭相似文件名确认。读取虚拟化列表时使用稳定业务 ID 和实际加载范围；不能拿 DOM 当前可见行数当整批 coverage。

回填须保留富文本/标签、换行、锁、选区和输入节点语义。普通 fill 能填文本不证明适合 Phrase 每一种编辑器，必须通过合成同类控件验证并选用能保结构的原生动作。

保存、段确认、整项任务完成、TM 写入分别授权/验收。迁移与验收本身绝不访问真实 Phrase；只在今后用户明确任务中操作。客户账号登录和验证码不绕过，用户 help 未处理不能假称完成。

14.7 禁止默认网站调试副作用

BrowserSkill 的 network/console/debug 不是天然只读：请求 replay、rule modify/mock/block 会改变网络行为。LA 默认不开这些诊断，更不在 Phrase 上自动 replay 保存/提交请求。需要时使用单独明确任务；诊断记录也可能含客户正文，不能默认上传或长期采集。

15. 四岗位与完整 CAT UI

15.1 原生信息架构

在 DSH 原生侧栏增加一个 Linguist 入口，不替换 root/sidebar/conversation/composer。项目页提供创建/打开、批次与资源状态和进入会话。会话头只显示紧凑的项目、岗位、当前工作模式和必要状态。

CAT 用原生右区 page kind 与 body/title Slots；BrowserSkill 用它自己的 page kind。状态 keyed 到真实 Session+project+pane，不以最后全局变量决定内容。右区进入全屏/浮动/并排复用宿主控制；不把聊天复制到 CAT 页面。[S12]

工具结果提供能定位到 project/batch/segment/QA/proposal/context 的小锚点；点击才展开/导航，普通响应不能抢用户当前编辑焦点。新工具面板不可只显示原始 JSON。

15.2 确定的视觉原则

原生 DSH 主题与 --dsw-alias-* 语义变量、ui-primitives、CSS Modules 是唯一视觉体系。不引入第二套 Tailwind/组件库/global CSS，不把旧 Proma 整套样式带进 DSH。BrowserSkill 自身的已打包样式由其维护，不重写它的整个外观。[S13]

风格：低饱和、紧凑但可读；正文以 Source/Target 为中心，分隔线和状态克制；没有大面积渐变、装饰性看板、重复面包屑、多层卡片套卡片。中英文界面都做，默认跟随宿主；所有关键空态/错误/提示要完整，不泄漏内部错误栈给普通用户。

设计尺寸是目标值，不是覆盖宿主硬编码：CAT 正文约 14px、舒适行高 1.5 左右，信息元数据约 12px；顶栏约 40–44px；左右正文比初始近似 1:1、可调；批次导航初始约 180–220px 可收；参考检查器约 280–340px 可收；底部 QA/Proposal/历史区域可调，不占默认半屏。与 DSH token 不符时优先使用最接近的原生 token。

15.3 编辑布局

  • 上方：当前批次、语言、筛选/搜索、显示选项、必要动作；更多低频操作收进菜单。
  • 中央：稳定句段号/状态/锁、Source、Target 和 Tag 表示；活动编辑器视觉清晰。
  • 右侧检查器：TM/TB、Context、Voice/规范等按当前句段切换，尽量共享一次领域查询。
  • 底部：QA、Proposal、历史、任务进度，支持折叠和定位；批次进度不能混入整个项目。
  • 专注模式：原生全屏 CAT，退出时草稿、选区、滚动与可见面板不丢失。

普通 MacBook 宽度下不强行常开所有面板；窄窗口先折叠辅助区，编辑正文保持可操作。不要为适配手机删除桌面功能；本轮主验收是用户 Mac 本机桌面宽度。

15.4 编辑器完整交互

保留源的 IME composition、selection、undo/redo、hard Tag span、复制/粘贴、换行、快捷键、auto-size 等纯逻辑。只换宿主事件与视觉接缝，不改成普通 textarea 粗糙替代。

composition 期间不能自动确认/跳段/破坏撤销粒度。Enter/组合键遵循源定义，保存/确认不同。Tag/锁不能被 Backspace、全选覆盖或截断复制意外删掉；显示转换不改原生存储结构。CJK、emoji、组合字符、RTL 与 Windows 换行至少覆盖边界。

草稿与服务器当前版本分离；保存使用 baseRevision。冲突保留草稿并显示差异，提供明确重新应用/放弃，不自动覆盖。网络失败不清草稿；页面关闭/切批次时未保存草稿保留或按原流程提示。测试草稿存储与工作数据，不将客户正文默认存到通用分析缓存。

虚拟化必须稳定 key；活动编辑器不随消息流/无关统计重新挂载。用户选区、IME、undo 栈不能因 Agent 工具结果流而重置。

15.5 QA、Proposal 和参考

保留全部既有管理能力，不只读。QA 可定位、分类、处置、查看新鲜性；Proposal 可逐项/组接受拒绝、检查差异/冲突和来源；TM/TB、Style Guide、Voice、Context/图像、Tag Profile 均可按源功能管理。

必要规则/forbidden 冲突不能被可选的 topK 清空。上下文图像要真实显示且可通过附件进入模型，文件名或缩略图目录不算已看图。已批准样例不能从未验收的 Agent 输出自动升级。

15.6 加载、空态、错误与可访问性

读取中保留已有可用数据和局部 loading，避免整屏反复闪空。无批次显示导入入口；无项目显示创建/打开；损坏/归档显示真实只读原因；能力缺失指向具体配置，不显示通用“出错了”。

按钮均有文字或可访问名称；键盘焦点、Tab 顺序、菜单 Escape、恢复焦点遵循 DSH。尊重 reduced-motion、系统缩放与浅深色主题。所有成功、冲突、错误状态均不能只靠颜色辨别。

16. 自动任务与通用 Agent 能力

迁移现有 automation-context 的项目/岗位/范围/来源捕获，使用 DSH 原生 schedule/任务入口。创建时冻结明确输入/授权快照，执行时重新验证项目存在、归档、版本和可用模型；不让来源会话删除导致换项目，也不借调度获得新客户权限。

调度执行结束和专业任务完成分开。恢复、队列和 steer 使用原生 Session/inbox，不建第二持久队列。文件缺失、浏览器需要用户登录时如实阻塞该任务，不后台自动完成 Phrase 状态。

普通 DSH 功能不复制：Skills、MCP、模型/凭据、项目指令、文件/终端、通用协作都保持宿主原生方式。所选 DSH 缺少原 Proma 某个通用生活工具，不伪造接口，也不为迁移重写日历/邮件产品；但 LA 专业项目与范围在原生调度中必须完整可用。

17. 数据兼容、存储与回退

17.1 本轮不执行客户数据搬家

新产品默认使用独立数据根，不自动扫描并导入 ~/.linguist-agent、不指向正在使用的旧 cat.db、不复制或修改真实 OSgame。旧项目用户未来通过显式“打开/导入备份”接入；本轮在合成 schema/备份夹具上证明兼容。

同一份运行中 DB 不能由旧 LA 和新 DSH 两个产品竞争写。用户以后导入时，读旧备份/一致性副本→验证→写新根，旧原件保持不动。若版本更高不可读，明确拒绝，不降 schema 或清字段。

17.2 需要保留的数据

项目/批次/句段 ID、原件字节、Tag metadata、锁、目标版本、QA、Proposal、阶段决定、导出引用、TM/TB 来源、Context/Voice/规范、备份与历史责任均沿用源合同。不重建清空所有历史来获得漂亮的新 UI。

旧 Pi 会话不能伪装成新 DSH 可续跑记录。可提供按用户显式选择的只读旧日志/报告入口，原事实完整保留，但旧 actor 的完成证据不能冒充新 Session 本人已审校。

17.3 回退不靠丢数据

新版本安装到独立 immutable runtime 子目录，更新 current 指针前验证。失败保持旧新产品 runtime 和数据可用。卸载插件只卸代码，删除项目/数据走用户显式操作。停止脚本不删数据，不扫描 kill 同名系统进程。

如果新 metadata 必须升级，先保存一致性备份并采用明确版本 reader；不要“可回退”却在启动时无条件破坏性迁移用户根。本次只执行合成数据验证，不把这些数据操作对真实用户库自动运行。

18. 第三方插件取舍与隐私默认值

必装 BrowserSkill：完整浏览器能力及第 14 节文件传输接缝。它是能力依赖，不是第二个宿主。

dsh-context 可选诊断配置：准备可安装、可启用的固定配置；默认日用不开常驻分析。读取 DSH 原生投影用于定位上下文/重复输出，不把它变成每次审校的前置步骤。其失败不应拖垮 LA 核心；未验证不得称其“已安装成功”。

WeKnora/dsh-library：本轮不部署知识平台、不重复索引客户资料。保留现有 LA Context/TM/TB 能力和外部知识接口可扩展性即可；未来启用时采用项目限定、原文检索、明确截断，默认不委派第二模型 ask。

不集成 Ruflo、自动降级/续跑/记忆蒸馏、多层审批模型、替代侧栏和图表平台。此项不是削减 LA 现有能力，而是不把可选生态产品变为迁移依赖。

新独立 profile 显式关闭 DSH session-log-deepseek 的额外 Session-log 请求字段和非必要产品分析/反馈外发，保留正常模型请求。用配置和 mock 请求捕获验证，不全局 monkeypatch fetch，不影响用户其它 DSH profile。当前官方该日志插件默认 enabled；不能说“本地程序所以不外发”。[S14]

BrowserSkill 预览保留本机路径/同源策略，不默认开启网站调试、操作审计或云转发。模型、embedding、OCR、自动标题等辅助调用均沿用用户可见配置；不能擅自另找 Provider 发送客户材料。

19. 权限与无人值守的实际边界

19.1 个人工具，不建设企业权限体系

同一 DSH 用户权限作用于 LA 与通用工具；岗位不另外收紧工具清单。已批准任务范围内的正常读取/保存不重复问用户。数据完整性门禁（CAS、Tag、锁、历史、范围）仍不可关掉换速度。

用于施工的权限与产品今后操作客户任务的权限不同：无人值守迁移允许安装依赖、启动合成测试，不等于授权点击真实 Phrase 的完成按钮。

19.2 能自动做的做完

自动完成新仓库初始化、必需私有工具链、构建、兼容补丁、实际 tgz 经官方 Desktop 原生插件管理安装、独立 desktop profile 配置、UI/合成/模型 smoke、桌面入口、重新打开测试、最终通知。不要以“安装留给用户”提前交差。

自动使用已正常配置的 DSH 模型与已连接 BrowserSkill 的公开接口；可从用户明确的正常配置入口取得必要值，凭据只在内存/受支持凭据存储中流转，日志只记录模型和成功/失败元数据。不要把 env、token、key、Cookie 打进报告或测试快照。

19.3 不能凭空完成的前置条件

没有 Provider 凭据/授权，不能造一条模型成功记录；浏览器扩展未装/未连接，不能把 CLI version 当浏览器可用；系统/浏览器要求用户确认，不能通过改 policy、禁用保护、偷 Cookie 或假点击绕过。BrowserSkill 官方安装指南明确把扩展安装/连接交给用户。[S11]

最初侦察就发现这些问题，写入 STATE.json 的外部 prerequisite 项，继续全部不受阻的代码和合成验证。没有必要每个阶段问一次。最终如果仍缺必需条件，发送 “实现已完成，环境尚未就绪” 或 “任务受阻” 通知，列出唯一缺口；禁止发送“打开即用”。

不能因为一个模型路由/浏览器未连，就只交 README、隐藏按钮或删掉对应功能。真实产品功能照常实现，隔离 mock 合成覆盖照常完成；但 mock 不能顶替最终实际路由/扩展就绪 gate。

19.4 自动恢复的限制

本地测试失败、类型错误、UI 问题、缺资源、插件加载失败属于施工问题，必须修复并继续，不申请用户确认。不以“已经完成前几步”“一次会话太长”自行降低目标。

网络短暂失败可以有限重试并记录原因；401/403、需要交互授权、磁盘只读/满、真实系统权限拒绝不能无限重试或更换无关账户。宿主配额/执行时限若终止运行，保存接续记录，不能创建未经批准的外部自运行服务绕过限制。

20. 真正可安装的构建与依赖

20.1 一套明确工具链

新仓库使用独立 pnpm workspace，与目标 DSH 的 Node/ESM 边界一致。旧 Bun 专属调用只在必要测试/脚本适配，不把 Pi/Electron 当产品依赖。项目私有 Node 必須满足 node:sqlite 实测要求；不要修改用户全局 Node、brew 环境和 shell profile。

DSH/BrowserSkill 兼容所需的新依赖允许固定引入；不升级与迁移无关的领域 parser。pnpm 的共享 Host 依赖用 peers/external 保持单例，不能只版本相同却装出两个 Cordis/scope/React 实例。

20.2 Host 与 Client 打包

LA Host 可将自己拥有的领域实现和纯库打入产物；DSH/Cordis/共享 React 不私有复制。Client 采用 DSH 当前 module-loader 认可的 ./client 产物与 dsh.client manifest，资源路径由包位置解析，不依赖 cwd。

TypeBox/DSH schema/JSON value 适配通过编译和真实注册验证。API bridge 不依赖 Typert 生成的 out-of-tree Remote；DSH 自己的 Client 服务按其公开类型正常消费。静态包与动态插件的 external 规则不得混用。

worker、角色、Skills、i18n、图标、格式资源、许可必须包含在 npm pack 实际 file list。禁止发布 .ts 源引用未编译 runtime、绝对源路径、未解析 workspace:*、node_modules 里的偶然可见文件或测试 fixture 作为运行必需。

20.3 必须提供的项目命令

这些是目标仓库要实际实现的命令，不是当前声称已存在的 DSH CLI：

命令 合同

21. 独立本机安装与双击使用

21.1 本轮确定的日用载体

固定版本的官方 DSH Desktop 成品＋LA/BrowserSkill 原生 Host+Client 插件。本机 ARM64 安装包须与锁定的 DSH runtime 保持同一完整版本（当前 0.1.7-rc.2）；从官方发布地址取得并记录下载摘要、签名/公证状态及实际 bundle 版本。使用官方 Electron 窗口、Host、插件管理和停止机制，不构建或维护自己的 Electron 壳。既有 Web profile 仅可作为开发诊断，不能计入正式桌面验收。

桌面入口打开官方 Desktop 的 dsh-app://app 产品窗口，实际显示 Linguist 项目入口、完整 CAT 工作台与 BrowserSkill 面板。若为保持独立产品数据根需要轻量入口，它只设置 DSH_HOME 和 Chromium --user-data-dir，再启动未修改的官方 .app；不得加载另一套 UI、Agent loop 或 Web 宿主。

desktop profile 由官方 Desktop 独占。不得用 CLI 启动或管理它。 LA 与 BrowserSkill 的实际 tgz 通过官方 Desktop 插件管理流程安装、启用、重开并核验。同版本 Web profile 的通过记录不能代替 Desktop 包的 Host/Client/插件证据。[S09]

21.2 安装身份和固定命令

为本产品使用 Application Support 下的新 DSH_HOME。当前固定的 0.1.7-rc.2 成品不实现较新文档中的 DSH_DESKTOP_USER_DATA_DIR；本机以 Electron/Chromium --user-data-dir 启动参数隔离浏览器数据，须实测数据确实写入独立目录。安装前检查当前默认 ~/.dsh、旧 LA/Proma 和可能已有的官方 Desktop 路径；任何同名或同 bundle ID 实例都不得被覆盖或借用。官方 Desktop 使用其自己的 desktop profile 与内置 pnpm；不得把 Web profile 的 node_modules、patch 或 CLI 插件事务复制进去。

下载使用官方固定版本地址，记录包摘要与来源，并核对 bundle 内嵌 dsh/桌面版本。插件安装遵循官方 Desktop 插件管理界面或其公开产品 API；安装后读取 Desktop 实际 profile 清单和运行状态，确认两个 tgz 各有唯一启用实例。插件配置使用此独立 DSH_HOME/cordis.patch.yml 官方用户层；不能直接改官方受管 desktop profile 文件、绕过其管理事务，或以同名 Web profile 假装安装成功。若当前官方成品缺少必需的隔离或插件能力，记录准确的 FAILED/BLOCKED_ENV，修复可修的薄插件适配并继续其它工作。

无默认第三方 mirror/随机 npx latest，不擅改全局 npmrc。只在本产品独立数据根写配置；保留用户之后在该环境选择的 provider、权限和模型。

21.3 后台进程与端口

正式 Host 生命周期、单实例和本机端口由官方 Desktop 管理；不再为 DSH Web 创建 launchd job。BrowserSkill 如需独立 CLI daemon，必须使用本产品私有目录和官方插件约定，不能重复创建第二个浏览器控制链。关闭 Desktop 后检查其自有 Host 是否停止，不能误停用户其它 DSH 实例。

Desktop 仅绑定 loopback。启动/重开时核对官方窗口、内嵌 Host 版本、DSH_HOME、LA installationId、BrowserSkill 实例和插件实际装载；无法核对时不得称成功。二次双击复用官方实例而不重复开启写库 Host。

24. 无人值守施工组织与并行规则

24.1 执行循环

每个工作包：读对应源与本规范→迁实现→针对性验证→修到通过→记录目标/证据/提交→继续下一包。中途回复进展不等于交付；不要在出现第一次绿色测试后结束会话。

24.2 并行边界

可并行：领域机械抽离、UI 在稳定 DTO 下迁移、BrowserSkill 薄适配、安装器/验证夹具。合同与锁文件只有一个集成负责人写；两个子任务不能同时改同一根 package/绑定/evidence 文件。给每个施工子任务交付明确本地路径、任务范围、输入与预期产物，不引用“上面说过的”。

父任务保持全量功能和完成状态责任，不能以子任务“completed”代替实际合并/安装验收。只把同一份完整规范给负责跨域的人；局部子任务引用相关章节和合同，避免重复灌入全部历史。

24.3 长任务与上下文

按工作包保存 STATE.json/NEXT.md 和测试输出位置；模型压缩后重新读状态、当前 diff 和相关章节，不重新研究整套宿主。引用源码时按已确定路径精读，不连续倾倒整仓。

宿主限额确实结束运行时，留可接续状态；通知只能写“执行中断/受阻”，不能伪装成完整迁移。不存在“把任务交给另一个隐藏模型无限接力”作为默认执行方式。

30. READY 门禁：只有 verifier 可以发放成功

30.1 三种结束状态

  • READY：完整功能、实际安装、真实模型与已连接浏览器合成smoke、桌面重开和全部安全/质量gate通过，可以正常打开开展新任务。
  • BLOCKED_ENV：代码/合成可已完成，但缺用户凭据/浏览器扩展/系统许可等确实外部条件；逐项写明已完成与未验证，不称打开即用。
  • FAILED：仍有必需功能/集成/运行/数据完整性错误；继续修复可修问题，若基础设施确实阻断则保存证据报告失败。不能通过改计划将其升级为READY。

工作中还可使用 IMPLEMENTING/VERIFYING。没有模糊的 READY_WITH_MISSING_BROWSER 或“技术上完成，核心以后再做”。

30.2 所有成功gate都是AND

G01 本地实际功能映射全部有真实目标和证据，无必需TODO/空壳； G02 所有角色、CAT/工作副本/网页路径完整； G03 领域ID、格式、Tag/锁/CAS/QA/历史和专业证据回归通过； G04 真正安装tgz、Host/Client/资源/worker均加载，运行无需源目录或Proma； G05 两Session作用域、HTTP/SSE、子任务、取消/恢复正确； G06 实际UI可操作并有安装版本截图； G07 正常配置Provider真实合成任务通过，非mock； G08 BrowserSkill实际CLI/daemon/extension/plugin链及文件传输合成任务通过； G09 新产品独立data/profile，旧源/旧数据/客户网站未被修改； G10 固定官方 Desktop 成品的独立入口双击→退出→重开通过，desktop profile 中两个插件仍激活，施工 shell 结束不影响运行； G11 源功能快照、最终代码、产物、安装实例和证据身份一致； G12 无未处理的强制外部prerequisite，无默认额外客户日志外发。

30.4 完成通知

notify.mjs 只能读取刚生成、与当前安装匹配的READY收据。成功时发本机通知“Linguist Agent DSH 已完成并验证，可从桌面打开”，同时给出真实入口和报告路径。系统不允许通知时，保留桌面/仓库显著的结果报告和会话最终消息，不能声称系统通知已送达。

BLOCKED_ENV/FAILED采用明确受阻/失败文案，不播放成功提示。通知不发客户邮件、不发公开消息、不自动push。发送通知是施工执行者在真正结束时做的动作，本方案制定过程并未启动后台迁移或预约通知。

31. 最终给用户的交付消息模板

真实READY时说明：完整迁移已完成；桌面app实际路径；实际DSH/LA/BrowserSkill安装身份；通过的三条业务路径；只做合成验证、未操作真实Phrase/客户数据；一处查看完整报告；一条停止/回退方式。用最少文字，不把日志和测试表全部倒给用户。

受阻时说明：哪一项真实环境条件缺失；代码/安装/合成分别完成到哪里；准确尚未通过的gate；成果与可接续文件位置。不要把任务重新推回用户做研发，不问已经给过答案的问题，不把缺扩展说成“代码很难所以先MVP”。

32. 执行者在准备结束时必须避免的误判

“源码里有这个函数”≠“已安装插件能调用”；“页面打开”≠“四岗位可用”；“模型说改好了”≠“目标已保存”；“工具结果返回了全文”≠“最终Provider收到全文”；“子任务completed”≠“全范围审校完成”；“bsk doctor”≠“DSH Skill发现/浏览器文件传输已验证”；“同版本号”≠“同产物”；“测试多”≠“质量高”；“功能齐全的旧LA”不等于新宿主接缝自动正确。

本任务最终价值是完整专业能力在一个不再依赖Proma的DSH插件中真实运行，减少维护负担与无谓操作。完整迁移和工程分步并不矛盾；不能把工程分步当裁剪目标的理由。
